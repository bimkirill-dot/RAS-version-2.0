# RAS v. 2.0 — практические заметки

Сначала прочитать `PRINCIPLES.md` (принципы плагина), `MODULE.md` и `DECISIONS.md` модуля, с которым работаете. Здесь — как собрать, проверить и выпустить.

- ИИ делает коммиты, а выгружает разработчик сам (`git push`) — ИИ только напоминает и подсказывает команды.

## Сборка и выпуск

| Команда | Что делает |
|---|---|
| `build.cmd` | Собирает всё под Revit 2023 и 2026, запускает проверки, кладёт сборку в `out\Releases`, ставит себе загрузчик (если он изменился) и пишет `%AppData%\RAS_v_2.0\loader.ini` — на этом компьютере загрузчик берёт сборки из `out\Releases`. Revit можно не закрывать: новая сборка подхватится при перезапуске. |
| `publish.cmd [test\|all]` | То же + выпуск на сервер (`RasPaths.ServerRoot`) в канал «тест» или «все». Спрашивает «что нового». |
| `promote.cmd` | Сборку канала «тест» — всем, без пересборки. |
| `rollback.cmd [all\|test]` | Вернуть каналу одну из прежних сборок. |
| `status.cmd` | Что сейчас у каналов «тест» и «все»: версия, когда выпущена, что нового; последние выпуски, тестовая группа. Ничего не меняет. |
| `icons.cmd` | Иконки кнопок из SVG (`Icons\<имя>.svg` модулей и ядра): PNG 32 и 16, светлые и тёмные, и лист просмотра `out\icons-preview.png`. Стиль и палитра — `tools\IconBuilder\СТИЛЬ.md`. |
| `site.cmd [start\|stop\|rollback\|autostart]` | Сайт RAS-Clash Analysis на этом компьютере (`tools\Site.ps1`): без параметра — проверки, сборка, копия базы, замена программы, запуск и браузер (`http://localhost:5080`). Не связан с выпуском плагина. Подробно — `MODULE.md` модуля, «Сайт». |
| `publish-setup.cmd` | Собрать, проверить и выложить установку в `Setup` на сервере: `install.cmd` + загрузчик для Revit 2023 и 2026. Только когда изменился загрузчик или скрипт установки. |

- Установка у пользователя — `setup\install.ps1` (запускает `install.cmd`): загрузчик и манифест в `%AppData%\Autodesk\Revit\Addins\<год>` для каждой установленной версии Revit, уборка прежних установок RAS-Model History / SpyPlugin. `build.cmd` ставит загрузчик разработчику этим же скриптом (`-Dev`).
- Логика скриптов — `tools\Release.ps1` (Windows PowerShell 5.1; файл в UTF-8 **с BOM**, иначе русский текст искажается).
- Проверочная сборка одного проекта: `dotnet build "<проект>.csproj" -c Release -p:RevitVersion=2023` (или `2026`). Результаты — `out\bin\<год>\loader | parts | tests`.
- Проверки логики: `out\bin\<год>\tests\RASv2.Tests.exe` (код возврата 0 — прошли). Сборка и выпуск без прошедших проверок не идут.
- Чтобы на компьютере разработчика брать сборки с сервера, как у всех, — удалить `%AppData%\RAS_v_2.0\loader.ini`.
- Загрузчик занят, пока открыт Revit: если `build.cmd` пишет, что загрузчик не обновлён, — закрыть Revit этой версии и повторить. Сборки (ядро, модули) это не касается.
- Журналы: загрузчик — `%LocalAppData%\RAS_v_2.0\Logs\loader.log`, ядро и модули — `...\Logs\ras.log`.
- Проверить работу в Revit автоматически нельзя — проверяет пользователь. После изменений: собрать, перечислить, что посмотреть в Revit (в каждой поддерживаемой версии).

## Выпуск — по шагам

Для разработчика то же простыми словами — `Как выпускать.md` в корне: менять его вместе с этим разделом.

**Первый раз**
1. `publish-setup.cmd` — выложить установку (`Setup` на сервере). Дальше — только когда изменился загрузчик или `setup\install.ps1`.
2. `publish.cmd test` — первая сборка в канал «тест». Если нет `Config\test-users.txt`, он создаётся с вами. Тестовая группа — логины Windows без домена (`%USERNAME%`, например `Poletayev_BIM`), по одному в строке; `#` — комментарий.
3. Проверили в Revit 2023 и 2026 — `promote.cmd`: та же сборка всем.
4. Коллегам — ссылка на установку `\\10.10.1.77\Shared\BIM\00_Плагины\00_RAS\RAS_v_2.0\Setup\install.cmd` и раздел «Установка» из `README.md`.

**Обычный выпуск**
1. Изменения закоммичены (`publish.cmd` предупредит, если нет).
2. `publish.cmd test`, «что нового» — коротко, по-русски, для людей (это увидят пользователи).
3. Тестовая группа перезапускает Revit и проверяет.
4. `promote.cmd`. Срочное исправление — сразу `publish.cmd all`: он переводит на ту же сборку и канал «тест» (тестовая группа всегда берёт «тест» — иначе осталась бы позади всех; так было 08.10.2026).

**Если что-то пошло не так**
- Сборка мешает работать — `rollback.cmd` (у всех) или `rollback.cmd test`: канал возвращается на прежнюю сборку, пользователям — перезапуск Revit.
- Мешает один модуль — выключить его у всех в `Config\\modules.txt` (`README.md`, «Выключить модуль у всех»), пока готовится исправление.
- Выпуск прервался — не страшно: сборка копируется во временную папку, указатель канала меняется последним; повторить `publish.cmd`.

**Изменился загрузчик** (редко)
1. `build.cmd` ставит новый загрузчик вам — проверить запуск в Revit 2023 и 2026 (закрыть Revit перед `build.cmd`).
2. `publish-setup.cmd` — покажет, что загрузчик изменился, и выложит установку.
3. У тех, кто уже установил плагин, новый загрузчик — только после повторного `install.cmd`: сообщить всем.

## Устройство

- `Directory.Build.props` — общее для проектов: версия Revit (`RevitVersion` → net48 / net8.0-windows, константа `REVIT2023` / `REVIT2026`), ссылки на Revit API (`UseRevitApi=true`), папки вывода, `obj\<год>`.
- `src\Shared\RasPaths.cs` — адреса (сервер, локальные папки); подключён в загрузчик и ядро, скрипт выпуска берёт адрес сервера отсюда же.
- `src\Loader` — загрузчик (`BuildResolver` — выбор сборки, без Revit API, проверяется тестами; `LoaderApp` — вход из Revit).
- `src\Core` — ядро (`Host` — запуск модулей и ленты, `IModule` / `IModuleContext` — контракт с модулями, `Log`, `AboutCommand`); решения и планы ядра — `src\Core\DECISIONS.md`.
- Лента: модуль объявляет кнопки (`IModuleContext.AddButton`, код `<Id модуля>.<кнопка>`), ядро ставит их по раскладке `src\Core\ribbon.txt`: `[[Отдел]]`, `[Панель]`, коды кнопок, `подпись="…"` (`""` — без подписи), стопки маленьких кнопок `( … )` — синтаксис в начале файла (логика — `RibbonLayout`, с тестами; постройка — `RibbonBuilder`). Коды и подписи кнопок — в «О плагине». Кнопка без раскладки — на панели с названием модуля. Раскладка едет в сборку: поменять — правка файла, `build.cmd` / `publish.cmd`, перезапуск Revit. Коды кнопок после выпуска не менять. Иконки — в едином стиле (`tools\IconBuilder\СТИЛЬ.md`): рисуются в `Icons\<имя>.svg` папки модуля, PNG (32, 16 и тёмные `.dark`) делает `icons.cmd`, вшиты в сборку (в `.csproj` — `EmbeddedResource` с `LogicalName="Icons.%(Filename)%(Extension)"`); кнопка получает их по имени — `AddButton(…, icon: "<имя>")`; при смене темы Revit ядро меняет иконки само. Отдел модуля (цвет акцента) — `Icons\department.txt`. Коммитятся и SVG, и PNG.
- Общие настройки на сервере (`Config`): `test-users.txt` (тестовая группа, читает загрузчик), `modules.txt` (выключение модулей, читает ядро — `ModuleSwitches`, `ServerConfig`: не дольше 3 с, копия в `%LocalAppData%\RAS_v_2.0\Config`). Код модуля (`IModule.Id`) = окончание имени сборки `RASv2.<код>.dll` — на этом держится «не загружать».
- `src\Modules\<папка модуля>` — модули; у каждого `MODULE.md` (как устроен) и `DECISIONS.md` (решения с причинами, планы, идеи). Сейчас: `RAS-Model History` (переезжает из `D:\Code\SpyPlugin`, ход переезда — в его `MODULE.md`); `RAS-Clash Analysis` — разбор отчётов Navisworks (`Reports\`, с тестами) и сайт (`Site\`, `site.cmd`; `build.cmd` его не собирает — `*.Site.csproj` исключены в `tools\Release.ps1`); проекта модуля в Revit (мост) ещё нет.
- `tests\RASv2.Tests` — проверки логики: консольная программа без сторонних библиотек, логику подключает исходниками (`Compile Include`).

## Правила, о которые уже спотыкались

- Сборки 2023 и 2026 из одних исходников: служебные файлы каждой версии — в `obj\<год>`, и папки `obj` / `bin` исключены из исходников (`DefaultItemExcludes`). Без этого сборка 2026 подхватывает сгенерированные файлы сборки 2023.
- Одна копия каждой сборки плагина в процессе Revit: загрузчик и ядро грузят сборки в свой контекст загрузки (`LoadAssembly`), кнопки ленты указывают на ту же сборку (`Assembly.Location`). «О плагине» предупреждает, если кнопка попала во вторую копию.
- Коммит git в сборки не пишется (`IncludeSourceRevisionInInformationalVersion=false`): иначе DLL загрузчика менялась бы с каждым коммитом, и `build.cmd` просил бы закрыть Revit ради «нового» загрузчика. Коммит сборки — в её `build.txt`.
- Модуль, который ещё не работает в какой-то версии Revit, под неё собирает только своё описание (`IModule` с `RevitYears`): так «О плагине» показывает «не работает в Revit 2023», а решение собирается под обе версии (пример — `RASv2.ModelHistory.csproj`).
- Класс доступности кнопки (`AvailabilityClassName`, «доступна и без открытой модели») Revit ищет в сборке команды кнопки — поэтому он свой у ядра (`RASv2.Core.AlwaysAvailable`) и у каждого модуля; общий из ядра для кнопки модуля не работает.
- Пустую подпись кнопки (`ItemText = ""`) Revit API не принимает, невидимые знаки (U+200B) — тоже: кнопка без подписи — через внутреннюю ленту Revit (`AdWindows.dll`, `ShowText = false`, `RibbonBuilder`).
- Предупреждение MSB3277 (конфликт внутри ссылок Revit API 2026) переведено в сообщения — настоящие предупреждения не должны в нём теряться.

## Стиль

- Весь текст интерфейса — по-русски, коротко, «ёлочки», без англицизмов. Комментарии в коде — по-русски.
- Окончания строк: `*.cs`, `*.csproj`, `*.props`, `*.xaml`, `*.json`, `*.md` — LF; `*.cmd`, `*.ps1` — CRLF (`.cmd` — UTF-8 без BOM, `.ps1` — с BOM). Проверять через Python (`b.count(b'\r\n')`).
