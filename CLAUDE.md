Сначала прочитать `PRINCIPLES.md` (принципы плагина), `MODULE.md` и `DECISIONS.md` модуля, с которым работаете. Здесь — как собрать, проверить и выпустить.

- ИИ делает коммиты, а выгружает разработчик сам (`git push`) — ИИ только напоминает и подсказывает команды.

## Работа в команде

С 30.10.2026 над плагином работают несколько человек, у каждого свой Claude Code.

- **Ведущий разработчик** — логин Windows `Poletayev_BIM` (`LEAD` в `.claude\hooks\guard.py`): ядро, загрузчик, общие правила, проверка и слияние в `main`, выпуск. «Разработчик» в `PRINCIPLES.md`, этом файле и записях `DECISIONS.md` до 30.10.2026 — он.
- **Разработчики модулей** ведут свои модули: работают в своих ветках, в `main` не коммитят; готовое — запросом на слияние на GitHub. Порядок: `setup-dev` (один раз) → `start-task` → работа → `finish-change` → `submit-pr` → проверка ведущим (`review-pr`) → слияние.
- **Границы:** свой модуль — свободно; ядро, загрузчик, `src\Shared`, `tools\`, `setup\`, `Directory.Build.props`, чужие модули, `PRINCIPLES.md`, новые библиотеки, коды модулей и выпущенных кнопок — только по согласованию с ведущим (подробно — навык `start-task`, «Границы»).
- **Решения** по своему модулю принимает его разработчик; в `DECISIONS.md` — с именем и датой. Общее для плагина решает ведущий.
- **Модули и кто ведёт:** RAS-Model History, RAS-Clash Analysis, RAS-Sheet Manager — ведущий разработчик. Новый модуль — строка сюда вместе с первым запросом на слияние.
- **Проверки Claude Code** (`.claude\settings.json`, `.claude\hooks`; нужен Python): после каждой правки файла — окончания строк, BOM, невидимые знаки (`after_edit.py`); перед командой (`guard.py`) — не выполняются `git push`, выпуск (`publish`, `promote`, `rollback`, `setup`), запись в базу сайта коллизий, коммит и слияние в `main` не у ведущего. Причина приходит Claude — он подсказывает человеку команду.
- **Личное** — в `CLAUDE.local.md` в корне (не в git): кто ты, какой модуль ведёшь, свои привычки. Общие правила — сюда, через ведущего.
- **Узнали новое о порядке работы** — поправить навык в `.claude\skills` или этот файл в том же запросе на слияние; в личной памяти Claude это не дойдёт до других.

| Команда | Что делает |
|---|---|

Revit можно не закрывать: новая сборка подхватится при перезапуске. |
| `revit.cmd publish test\|all` (2, 3) | То же + выпуск на сервер (`RasPaths.ServerRoot`) в канал «тест» или «все». Спрашивает «что нового». |

| `revit.cmd rollback [test]` (5, 6) | Вернуть каналу («все», с `test` — «тест») одну из прежних сборок. |
| `revit.cmd status` (7) | Что сейчас у каналов «тест» и «все»: версия, когда выпущена, что нового; последние выпуски, тестовая группа. Ничего не меняет. |
| `revit.cmd setup` (8) | Собрать, проверить и выложить установку в `Setup` на сервере: `install.cmd` + загрузчик для Revit 2023 и 2026. Только когда изменился загрузчик или скрипт установки. |
| `icons.cmd` | Иконки кнопок из SVG (`Icons\<имя>.svg` модулей и ядра): PNG 32 и 16, светлые и тёмные, и лист просмотра `out\icons-preview.png`. Стиль и палитра — `tools\IconBuilder\СТИЛЬ.md`. |
| `site.cmd [start\|stop\|rollback\|autostart\|firewall]` | Сайт RAS-Clash Analysis на этом компьютере (`tools\Site.ps1`): без параметра — проверки, сборка, копия базы, замена программы, запуск и браузер (`http://localhost:5080`); `firewall` — открыть порт коллегам (один раз, права администратора). Не связан с выпуском плагина. Подробно — `MODULE.md` модуля, «Сайт» и «Вход на сайт». |
| `navisworks.cmd [build\|publish test\|publish all\|promote\|rollback [test]\|status\|setup]` | RAS v. 2.0 для Navisworks Manage 2023 (`tools\Navisworks.ps1`) — отдельно от Revit, двойной щелчок — меню: собрать и поставить себе (загрузчик-пакет `src\Navisworks\Loader` + сборка `src\Modules\RAS-Clash Analysis\Navisworks`, проверки, пакет — `setup\install-navisworks.ps1 -Dev`, `navisworks-loader.ini`), выпуск (`Releases\Navisworks\2023`, каналы «тест» / «все»), перевод на всех, откат, статус, установка для коллег (`Setup\Navisworks`: `install-navisworks.cmd` + пакет — только когда изменилась вкладка). Устройство — `src\Navisworks\README.md`, простыми словами — `Как выпускать.md`. |

- Установка у пользователя — `setup\install.ps1` (запускает `install.cmd`): загрузчик и манифест в `%AppData%\Autodesk\Revit\Addins\<год>` для каждой установленной версии Revit, уборка прежних установок RAS-Model History / SpyPlugin. `revit.cmd build` ставит загрузчик разработчику этим же скриптом (`-Dev`).
- Логика скриптов — `tools\Release.ps1` (Windows PowerShell 5.1; файл в UTF-8 **с BOM**, иначе русский текст искажается).
- Проверочная сборка одного проекта: `dotnet build "<проект>.csproj" -c Release -p:RevitVersion=2023` (или `2026`). Результаты — `out\bin\<год>\loader | parts | tests`.
- Проверки логики: `out\bin\<год>\tests\RASv2.Tests.exe` (код возврата 0 — прошли). Сборка и выпуск без прошедших проверок не идут.
- Чтобы на компьютере разработчика брать сборки с сервера, как у всех, — удалить `%AppData%\RAS_v_2.0\loader.ini`.
- Загрузчик занят, пока открыт Revit: если `revit.cmd build` пишет, что загрузчик не обновлён, — закрыть Revit этой версии и повторить. Сборки (ядро, модули) это не касается.
- Журналы: загрузчик — `%LocalAppData%\RAS_v_2.0\Logs\loader.log`, ядро и модули — `...\Logs\ras.log`.
- Проверить работу в Revit автоматически нельзя — проверяет пользователь. После изменений: собрать, перечислить, что посмотреть в Revit (в каждой поддерживаемой версии).

## Выпуск — по шагам

Для разработчика то же простыми словами — `Как выпускать.md` в корне: менять его вместе с этим разделом.

**Первый раз**
1. `revit.cmd setup` (пункт 8) — выложить установку (`Setup` на сервере). Дальше — только когда изменился загрузчик или `setup\install.ps1`.
2. `revit.cmd publish test` (пункт 2) — первая сборка в канал «тест». Если нет `Config\test-users.txt`, он создаётся с вами. Тестовая группа — логины Windows без домена (`%USERNAME%`, например `Poletayev_BIM`), по одному в строке; `#` — комментарий.
3. Проверили в Revit 2023 и 2026 — `revit.cmd promote` (пункт 4): та же сборка всем.
4. Коллегам — ссылка на установку `\\10.10.1.77\Shared\BIM\00_Плагины\00_RAS\RAS_v_2.0\Setup\install.cmd` и раздел «Установка» из `README.md`.

**Обычный выпуск**
1. Изменения закоммичены (выпуск предупредит, если нет).
2. `revit.cmd publish test` (пункт 2), «что нового» — коротко, по-русски, для людей: этот текст каждый увидит окном «Что нового» при первом запуске Revit с новой сборкой (один раз; `src\Core\WhatsNew.cs`, `notes.txt` сборки).
3. Тестовая группа перезапускает Revit и проверяет.
4. `revit.cmd promote` (пункт 4). Срочное исправление — сразу `revit.cmd publish all` (пункт 3): он переводит на ту же сборку и канал «тест» (тестовая группа всегда берёт «тест» — иначе осталась бы позади всех; так было 08.10.2026).

**Если что-то пошло не так**
- Сборка мешает работать — `revit.cmd rollback` (у всех, пункт 5) или `revit.cmd rollback test` (пункт 6): канал возвращается на прежнюю сборку, пользователям — перезапуск Revit.
- Мешает один модуль — `выключен` в блоке `{Модули}` файла `src\Core\ribbon.txt` и сразу `revit.cmd publish all` (или `revit.cmd rollback`), пока готовится исправление (`README.md`, «Модули и кнопки у всех»).
- Выпуск прервался — не страшно: сборка копируется во временную папку, указатель канала меняется последним; повторить выпуск.

**Изменился загрузчик** (редко)
1. `revit.cmd build` ставит новый загрузчик вам — проверить запуск в Revit 2023 и 2026 (закрыть Revit перед сборкой).
2. `revit.cmd setup` (пункт 8) — покажет, что загрузчик изменился, и выложит установку.
3. У тех, кто уже установил плагин, новый загрузчик — только после повторного `install.cmd`: сообщить всем.

## Правила, о которые уже спотыкались

- Сборки 2023 и 2026 из одних исходников: служебные файлы каждой версии — в `obj\<год>`, и папки `obj` / `bin` исключены из исходников (`DefaultItemExcludes`). Без этого сборка 2026 подхватывает сгенерированные файлы сборки 2023.
- Одна копия каждой сборки плагина в процессе Revit: загрузчик и ядро грузят сборки в свой контекст загрузки (`LoadAssembly`), кнопки ленты указывают на ту же сборку (`Assembly.Location`). «О плагине» предупреждает, если кнопка попала во вторую копию.
- Коммит git в сборки не пишется (`IncludeSourceRevisionInInformationalVersion=false`): иначе DLL загрузчика менялась бы с каждым коммитом, и `revit.cmd build` просил бы закрыть Revit ради «нового» загрузчика. Коммит сборки — в её `build.txt`.
- Модуль, который ещё не работает в какой-то версии Revit, под неё собирает только своё описание (`IModule` с `RevitYears`): так «О плагине» показывает «не работает в Revit 2023», а решение собирается под обе версии (пример — `RASv2.ModelHistory.csproj`).
- Класс доступности кнопки (`AvailabilityClassName`, «доступна и без открытой модели») Revit ищет в сборке команды кнопки — поэтому он свой у ядра (`RASv2.Core.AlwaysAvailable`) и у каждого модуля; общий из ядра для кнопки модуля не работает.
- Пустую подпись кнопки (`ItemText = ""`) Revit API не принимает, невидимые знаки (U+200B) — тоже: кнопка без подписи — через внутреннюю ленту Revit (`AdWindows.dll`, `ShowText = false`, `RibbonBuilder`).
- Предупреждение MSB3277 (конфликт внутри ссылок Revit API 2026) переведено в сообщения — настоящие предупреждения не должны в нём теряться.
- Ключ своего стиля в окне WPF не должен совпадать с кистью ядра (`Row`, `Line`, `Field`… — `WindowTheme`): 29.10.2026 стиль `Row` уронил окно на загрузке XAML, а ошибка, ушедшая сквозь вложенный `ShowDialog`, — весь Revit. Окно — проверять вне Revit (навык `new-button`), вложенное окно — в `try/catch`.
- Скрипты правок с обратной косой чертой (`\n`, `\\`, пути Windows) — файлом (Write → `python файл.py`), не heredoc в Bash: heredoc превращает `\\` в `\` и `'\n'` в настоящий перенос, в коде появлялись невидимые управляющие знаки (20.10.2026). Хук `after_edit.py` их ловит.
- Файл, давно открытый во вкладке VS Code, при сохранении затирает правки Claude старым текстом (23.10.2026, `Как выпускать.md`): после правки открытого файла — `git status`; затёрло — восстановить из коммита и подсказать «Revert File».

## Стиль

- Весь текст интерфейса — по-русски, коротко, «ёлочки», без англицизмов. Комментарии в коде — по-русски.
- Окончания строк: `*.cs`, `*.csproj`, `*.props`, `*.xaml`, `*.json`, `*.md` — LF; `*.cmd`, `*.ps1` — CRLF (`.cmd` — UTF-8 без BOM, `.ps1` — с BOM). Проверять через Python (`b.count(b'\r\n')`).
