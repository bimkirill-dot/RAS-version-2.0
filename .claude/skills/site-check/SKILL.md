# Проверить сайт коллизий

Разработчик смотрит сайт сразу через F5 на своём рабочем сайте (`http://localhost:5080`). Неработающее там раздражает, а в базе — его настоящие отчёты. Поэтому «готово» говорится только после двух вещей: пройдено в браузере на пробных данных и установлено.

## Жёсткие правила

- **Его база** (`%LocalAppData%\RAS_v_2.0\RAS-Clash Analysis\Site\clashes.db`) — только читать (`mode=ro`). Писать, править, переносить устройство базы — только в копии во временной папке.
- Пробный сайт — на своём порту (не 5080) и со своими папками данных и копий. Его сайт этим не задевается.
- Снимки экрана смотреть самому (Read на PNG): «скрипт прошёл» не значит «выглядит правильно».
- Ошибки к `127.0.0.1:5181`–`5185` в консоли (CORS, «connection refused») — это опрос моста в Revit, к правке не относятся.

## Шаги

Скрипты лежат рядом с этим файлом: `.claude\skills\site-check\`. Рабочая папка (`SP`) — scratchpad сессии.

1. **Проверки и сборка.** `dotnet build tests\RASv2.Tests\RASv2.Tests.csproj -c Release -p:RevitVersion=2023 -nologo -v q`, затем `out\bin\2023\tests\RASv2.Tests.exe` (код 0). Логика сайта подключена в тесты исходниками; новое правило в `Logic\` — новый случай в тестах.

2. **Окружение браузера** (один раз за сессию):
   ```
   python -m venv "$SP/venv-site"
   "$SP/venv-site/Scripts/python.exe" -m pip install -q selenium
   ```
   Edge-драйвер Selenium находит сам. Если в `Scripts` нет `python.exe` — окружение битое, создать заново под другим именем.

3. **Копия базы** (настоящие данные, пароль для входа — только в копии):
   ```
   python .claude/skills/site-check/site_data.py copy "$SP/sitecheck-data" --password secret1
   ```
   Печатает проекты, отделы, людей, отметки и отчёты — по ним выбрать, на каком проекте смотреть. Всем учётным записям копии ставится пароль `secret1`; вход — любым логином из напечатанных (администратор — `egor`, он же по умолчанию в `login()`; права сотрудника — логином с ролью `user`).
   Пробные данные, которых в копии нет (отделы, люди, отметки, разнесённые по дням), добавлять отдельным скриптом **в копию** — через Write в `SP`, не heredoc.
   Нужна пустая база (перенос устройства, первый запуск) — не делать `copy`: сайт создаст базу сам.

4. **Пробный сайт** — свежая публикация и запуск на копии:
   ```
   python .claude/skills/site-check/site_run.py start "$SP/sitecheck-data" --port 5099
   ```
   Публикует в `$SP/sitecheck-app`, ждёт «Now listening», журнал — `$SP/sitecheck-data/run.log`. `--scan 1` — если нужен разбор папок с отчётами (по умолчанию выключен). Остановить: `site_run.py stop`.

5. **Браузер.** Свой короткий скрипт в `SP` на основе `site_browser.py` (импорт `from site_browser import *` с `sys.path` на папку навыка):
   - `d = browser(1560)` — Edge без окна; ширины смотреть две: 1560 (его экран) и 900 (узкий);
   - `login(d, base)`; `open_project(d, base, id)`; `side(d, "Сводка")`, `sub(d, "Аналитика")`, `tab(d, "Динамика")` — переход как человек;
   - `shot(d, path)`, `page_errors(d)` (без шума моста);
   - навигация: подпункты боковой панели (`.side-sub`) видны только после щелчка по её разделу (`.side-btn`).
   Пройти то, что поменялось, и соседнее, что могло задеть (другие вкладки, отборы, Excel, тёмная тема, если трогали цвета). Печатать текст элементов, а не только «есть / нет».

6. **Посмотреть снимки** и сравнить с тем, что просил разработчик (его рисунок — дословно). Плохо — править и с шага 1.

7. **Остановить пробный сайт**: `python .claude/skills/site-check/site_run.py stop`.

8. **Поставить на его сайт:**
   ```
   powershell -ExecutionPolicy Bypass -File tools\Site.ps1 -Action update -NoBrowser
   ```
   Скрипт сам делает копию базы перед заменой и перезапускает сайт. Перед этим — закоммитить (или хотя бы собрать проверки): ставится то, что в рабочей папке.

9. **В ответе** — что проверено (по пунктам, с тем, что видно на снимках), что установлено, «обновите страницу (F5)». Если что-то не проверить на копии (например, нужны отметки людей с отделами, а их ещё нет) — так и сказать.

## Чего не делать

- Не запускать `site.cmd` без параметров для проверки: он ставит сайт разработчику и открывает браузер.
- Не трогать его базу «на минутку», даже чтобы поставить пароль.
- Не придумывать раскладку страницы — см. навык `ui-sketch`.
