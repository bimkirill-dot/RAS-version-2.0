# Передать на проверку

Проверяет ведущий разработчик со своим Claude (навык `review-pr`) — по `PRINCIPLES.md`, сборкой и проверками. Чем точнее описание, тем быстрее слияние.

## 1. Готово ли

- Навык `finish-change` пройден: проверки под 2023 и 2026, сборка, `check_files.py`, `MODULE.md` и `DECISIONS.md` своего модуля, всё закоммичено в ветке (`git status` — чисто).
- Обновить от `main` и прогнать проверки ещё раз:
  ```
  git fetch origin
  git merge origin/main
  ```
  Конфликт — разобрать вместе с человеком; в чужих файлах (ядро, чужой модуль, общие строки `ribbon.txt`) — брать версию `main` и спросить ведущего, если неясно.
- Посмотреть, что уходит: `git diff --stat origin/main...HEAD`. Файлы вне своего модуля — каждый должен быть объясним (раздел «Вне модуля» ниже). Лишнее (отладка, пробные файлы, `out\`, личный `CLAUDE.local.md`) — убрать.

## 2. Выгрузить ветку — делает человек

Хук не даст выполнить `git push` самому. Подсказать человеку команду:
```
git push -u origin <ветка>
```
и ссылку для запроса на слияние:
`https://github.com/bimkirill-dot/RAS-version-2.0/compare/main...<ветка>?expand=1`

## 3. Текст запроса на слияние

Готовым блоком, чтобы человек вставил в GitHub. По-русски, для ведущего разработчика:

```
Заголовок: <Модуль>: <что сделано — коротко>

## Что сделано
- …для человека в Revit: кнопка, окно, поведение

## Почему так
- ключевые решения (подробно — DECISIONS.md модуля, записи от <дата>)

## Проверено
- проверки логики 2023 и 2026 — прошли (сколько новых случаев)
- сборка Release.ps1 -Action build — без ошибок и новых предупреждений
- окна — снимок вне Revit (window_shot.ps1)
- в Revit 2023 / 2026 — что человек уже проверил сам, если проверял

## Что посмотреть в Revit 2023 и 2026
1. …конкретные шаги и что должно получиться

## Вне модуля
- src\Core\ribbon.txt — строки кнопок модуля …
- tests\… — …
(«нет» — если ничего)

## Открытые вопросы
- …
```
Последней строкой — строка о Claude Code из системного напоминания (для запросов на слияние).

## 4. После проверки

- Замечания — исправлять в той же ветке, отдельными коммитами («по проверке: …»), человек выгружает снова, запрос на слияние обновится сам.
- Не согласен с замечанием — объяснить в ответе на него, а не молча оставить.
- Слили — `git checkout main && git fetch origin && git merge --ff-only origin/main`, ветку можно удалить (`git branch -d <ветка>`).
