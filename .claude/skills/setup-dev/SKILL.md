# Подготовить компьютер разработчика

Цель — человек собирает плагин и видит свою сборку в Revit 2023 и 2026. Ничего не устанавливать молча: что нужно поставить — сказать человеку и дать ссылку или команду, он ставит сам.

## 1. Что стоит на компьютере

Проверить и показать таблицей «есть / нет / что сделать»:

| Что | Как проверить | Зачем |
|---|---|---|
| .NET SDK 8 или новее | `dotnet --list-sdks` | сборка |
| .NET Framework 4.8 Developer Pack | папка `C:\Program Files (x86)\Reference Assemblies\Microsoft\Framework\.NETFramework\v4.8` | сборка под Revit 2023 |
| Revit 2023 и 2026 | `C:\Program Files\Autodesk\Revit 2023\RevitAPI.dll`, то же `2026` | Revit API для сборки и проверка в Revit. Стоит в другой папке — сборка с `-p:RevitDir=…` (`Directory.Build.props`) |
| Git | `git --version`, `git config user.name`, `git config user.email` | работа с репозиторием; имя и почта — его собственные |
| Python 3 | `python --version` | проверки Claude Code после каждой правки (`.claude\hooks`) и скрипты навыков. Без Python хуки не работают — это первое, что поставить |
| Доступ к сервер-папке | `Test-Path \\10.10.1.77\Shared\BIM\00_Плагины\00_RAS\RAS_v_2.0` | общие настройки; выпуск — не его забота |
| Selenium (только для сайта коллизий) | `python -m pip show selenium` | навык `site-check`; не работает с сайтом — не нужен |

## 2. Репозиторий

- Доступ к приватному `bimkirill-dot/RAS-version-2.0` выдаёт ведущий разработчик (GitHub → Settings → Collaborators). Нет доступа — сказать, кого попросить.
- Клон: `git clone https://github.com/bimkirill-dot/RAS-version-2.0.git` в короткий путь без пробелов (например, `D:\Code\RAS_v_2.0`).
- Окончания строк делает `.gitattributes`; `git config core.autocrlf` должен быть `false` или не задан — иначе файлы `.cs` придут с CRLF. Проверить и подсказать.
- Логин Windows (`%USERNAME%`) — сравнить с ведущим разработчиком в `.claude\hooks\guard.py` (`LEAD`): у остальных коммиты в `main` запрещены, работа — в своих ветках (навык `start-task`).

## 3. Первая сборка

1. `powershell -NoProfile -ExecutionPolicy Bypass -File tools\Release.ps1 -Action build` — обе версии Revit, проверки, сборка в `out\Releases`, загрузчик себе и `%AppData%\RAS_v_2.0\loader.ini` (Revit на этом компьютере берёт сборки из `out\Releases`, а не с сервера). Revit перед первой сборкой закрыть — ставится загрузчик.
2. Ошибки сборки — разобрать по сообщению: чаще всего нет Developer Pack 4.8 или Revit не в стандартной папке.
3. Человек открывает Revit 2023 и 2026: вкладка «RAS v. 2.0», «О плагине» — номер сборки `dev`, его модули работают. Журналы — `%LocalAppData%\RAS_v_2.0\Logs\loader.log`, `ras.log`.
4. Вернуть сборки с сервера, как у всех, — удалить `%AppData%\RAS_v_2.0\loader.ini`.

## 4. Личное — `CLAUDE.local.md`

В корне репозитория, не коммитится (`.gitignore`). Предложить человеку записать туда:
- как его зовут и его логин Windows;
- какой модуль (модули) он ведёт;
- свои привычки («отвечай короче», «сначала план»).

Общее для всех — не сюда, а в `CLAUDE.md` через ведущего разработчика.

## 5. Что прочитать человеку

`README.md` (как устроен плагин для пользователей), `Как выпускать.md` (чтобы понимать путь сборки к людям — выпускает ведущий разработчик), `PRINCIPLES.md` (правила, по которым будут проверять его работу), раздел «Работа в команде» в `CLAUDE.md`. Затем — навык `start-task`.
