# Начать задачу

Разработчики ведут свои модули; ведущий разработчик (`LEAD` в `.claude\hooks\guard.py`) проверяет запросы на слияние, сливает их в `main` и выпускает плагин. Порядок — `CLAUDE.md`, «Работа в команде».

## 1. Ветка

```
git fetch origin
git checkout main
git merge --ff-only origin/main
git checkout -b <логин>/<код модуля>-<коротко-о-задаче>
```
- Имя ветки латиницей: `ivanov_kj/Partitions-otverstiya`. Одна ветка — одна задача: проще проверять и сливать.
- Незакоммиченные изменения в `main` перед этим — не терять: спросить человека, перенести в ветку (`git checkout -b` их забирает с собой).
- Уже есть ветка задачи — продолжать в ней; обновить от `main`: `git fetch origin && git merge origin/main` (не `rebase`, если ветка уже выгружена).
- Коммит в `main` хук не пропустит — это нормально, не обходить.

## 2. Прочитать до кода

1. `PRINCIPLES.md` целиком (по нему проверят работу — навык `review-pr`).
2. `CLAUDE.md` — сборка, «Работа в команде», «Правила, о которые уже спотыкались».
3. `MODULE.md` и `DECISIONS.md` своего модуля: многое уже решено, и решения с причинами.
4. Похожее в других модулях — как образец (читать можно, ссылаться и вызывать — нельзя).

## 3. Границы

- **Свободно:** папка своего модуля `src\Modules\<модуль>\`; свои тесты в `tests\RASv2.Tests\` (свой файл `<Модуль>…Tests.cs`, строка `Run(...)` в `Program.cs`, `Compile Include` в `.csproj`); строки своих кнопок и своего модуля в `src\Core\ribbon.txt`; строка своего модуля в «Планах» `CLAUDE.md`.
- **Только по согласованию с ведущим разработчиком:** ядро (`src\Core`), загрузчик, `src\Shared`, `Directory.Build.props`, `tools\`, `setup\`, чужие модули, `PRINCIPLES.md`, новые сторонние библиотеки, новый код модуля (`IModule.Id`) и коды кнопок, перенос кнопок на чужие панели. Нужно такое — остановиться, описать человеку, что и зачем, пусть согласует; согласовано — записать в `DECISIONS.md` («согласовано с …, дата»).
- Нужное нескольким модулям — не копировать к себе, а предложить перенести в ядро (`PRINCIPLES.md`, раздел 4).

## 4. Кто решает

- Поведение и интерфейс **своего модуля** — человек, с которым работаешь. Его решения — в `DECISIONS.md` модуля с его именем и датой («Иванов, 03.11.2026: «…»»).
- Общее для плагина (ядро, лента, данные на сервере, принципы, выпуск) — ведущий разработчик. «Разработчик» в `PRINCIPLES.md`, `CLAUDE.md` и старых записях `DECISIONS.md` — это он.
- Сомнение, не нарушает ли решение принципы, — спросить до кода.

## 5. По ходу

- Интерфейс — навык `ui-sketch`; кнопка — `new-button`; перенос из старого плагина — `port-feature`.
- Коммитить небольшими шагами в своей ветке (стиль сообщений — навык `finish-change`).
- Закончил — `finish-change`, затем `submit-pr`.
