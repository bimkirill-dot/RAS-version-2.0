# «Что нового» для выпуска

Текст вводится одной строкой на вопрос `Что нового — коротко, для людей` (`tools\Release.ps1`, `Read-Host`) и попадает в `notes.txt` сборки. Каждый пользователь увидит его один раз окном «Что нового» при первом запуске Revit с этой сборкой (`src\Core\WhatsNew.cs`); список выпусков — `revit.cmd status`.

## 1. Что вошло в выпуск

- Последняя выпущенная сборка: `\\10.10.1.77\Shared\BIM\00_Плагины\00_RAS\RAS_v_2.0\Releases\2023\test.txt` (канал «тест»; `all.txt` — «все») → номер сборки → `<номер>\build.txt`, строка `Коммит: <hash>`. Сервер недоступен — спросить разработчика, с какого коммита считать (или `revit.cmd status`).
- `git log --format="%h %ad %s" --date=short <hash>..HEAD` — что изменилось с тех пор.
- Отобрать только то, что **видят пользователи Revit**: новые кнопки и окна, изменённое поведение, исправленные ошибки. Не писать: сайт коллизий (он ставится отдельно, `site.cmd`), Navisworks (у него свой выпуск — `navisworks.cmd`, свой текст), документы, проверки, внутренние переделки, кнопки модулей в режиме `только тест` — их видит лишь тестовая группа (для выпуска в «тест» — можно, с пометкой).
- `Коммит: … + незафиксированные изменения` в прошлой сборке — уточнить у разработчика, что в ней было.

## 2. Как писать

- Одна строка (Enter завершает ввод). Несколько изменений — через «; ». Ориентир — 1–3 предложения, до ~300 знаков: это окно, а не журнал изменений.
- Для людей: название кнопки и панели, как на ленте («Менеджер коллизий» → «ID элемента связи»), что теперь можно сделать. Без имён классов, файлов, «рефакторинга», «фикса».
- По-русски, «ёлочки», без англицизмов (не «апдейт», «фича», «баг»; — «исправлено», «новая кнопка»).
- Исправление ошибки — что больше не происходит: «окно «Категории элементов» больше не закрывает Revit».
- Начинать с главного; мелочи — в конце или не писать.

Пример (выпуск 29.10.2026):
> «Показать в Revit»: видна рамка 3D-вида; новое окно «Настройки вида» — прозрачность, «Границы вида», «Категории элементов» с импортом и экспортом. «Менеджер коллизий»: новая кнопка «ID элемента связи» — номер элемента в связи с «Копировать».

## 3. Отдать разработчику

- Готовый текст — отдельным блоком, чтобы скопировать целиком.
- Рядом — какие коммиты вошли (по одному слову на каждый), чтобы он видел, что ничего не забыто.
- Напомнить порядок: изменения закоммичены и выгружены (`git push`), `revit.cmd publish test` (пункт 2), тестовая группа перезапускает Revit, затем `revit.cmd promote` (пункт 4). Срочное — `revit.cmd publish all` (пункт 3).
- Сам выпуск не запускать — только по явной команде разработчика (`PRINCIPLES.md`, раздел 15).
