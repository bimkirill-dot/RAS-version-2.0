# RAS-Clash Analysis — модуль работы с коллизиями

Единая база коллизий компании — по всем проектам и разделам — из отчётов Navisworks Clash Detective: сайт во внутренней сети (список, статусы, комментарии, ответственные, дашборды) и мост в Revit — этот модуль: показ коллизии в открытой модели по кнопке с сайта. Устройство — как в статье «Clash Analytics», с нашими улучшениями (`DECISIONS.md`).
Общие правила плагина — `PRINCIPLES.md` в корне, сборка и выпуск — `CLAUDE.md` в корне. Решения по модулю, планы и идеи — `DECISIONS.md` рядом.

## Зачем и для кого

- **Зачем.** Коллизии ищут в Navisworks, а исправляют в Revit; между ними — отчёты HTML и Excel, мессенджеры, копирование номеров элементов в «Выбор по коду». Нет ни общей картины («сколько коллизий, кто, где, как идёт»), ни удобного пути от коллизии к элементу.
- **Для кого.** Все: BIM-координатор загружает отчёты и раздаёт, проектировщики открывают свои коллизии в Revit и отмечают исправленные, руководители смотрят дашборды.
- Идея и устройство — статья «Clash Analytics» (habr.com/ru/articles/1033602), с нашими улучшениями (`DECISIONS.md`).

## Состояние

Обсуждается: устройство — в `DECISIONS.md` («Единая база коллизий»), пилот и этапы — там же («Пилот, проекты, этапы — уточнения»).

Есть разбор отчётов (`Reports\`, без Revit и без базы — общий для сайта и моста; проверки — `tests\RASv2.Tests\ClashReportTests.cs`):
- `ClashReport.cs` — отчёт как он есть: проверки, коллизии (guid, статус Navisworks, снимок, группа, точка, расстояние, дата обнаружения, оси), элементы (файл модели, уровень, категория, семейство, тип, имя, номер, весь путь);
- `ClashReportReader.cs` — чтение XML; не отчёт или битый файл — `InvalidDataException` с причиной по-русски; коллизия без элементов пропускается с предупреждением; дата отчёта — самая поздняя дата обнаружения, без неё — время файла;
- `ClashRules.cs` — «личность» коллизии (`IdentityKey`: проверка + номера двух элементов, `IdsKey`, без имени файла модели; одинаковые номера у разных моделей в одном отчёте — пара «файл + номер», `IdentityKeys` / `PairKey`; неполная пара — guid; `HasFullPair` — у всех элементов есть файл и номер), уровень для группировки (`LevelKey`), статус Navisworks → наш (`StateOf`), снимок (`ImageFile`), единицы.

Проверено на всех пяти отчётах S08 (143 коллизии): у всех есть номер элемента, файл модели, уровень и снимок.

**Сайт — первая версия пилота (09.10.2026)**, только для разработчика, на его компьютере (`http://localhost:5080`). **Мост в Revit — прототип (19.10.2026)**, только Revit 2026: «Показать в Revit» из карточки коллизии (раздел «Мост в Revit» ниже; договорённость — `DECISIONS.md`, «Мост в Revit: „Показать в Revit“ — договорённость»). Ждёт проверки в Revit.

## Сайт

Папка `Site\` — проект `RASv2.ClashAnalysis.Site` (ASP.NET Core, .NET 8, страницы — Blazor, обновление страниц через постоянное соединение с сайтом). Разбор отчётов — `..\Reports\*.cs` исходниками. Сборка плагина (`build.cmd`) сайт не собирает; свой запуск — `site.cmd` в корне (`tools\Site.ps1`):

| Команда | Что делает |
|---|---|
| `site.cmd` | проверки → сборка → остановка сайта → копия базы («Копии базы\перед обновлением …», 10 последних) → «Программа» становится «Программа.прежняя», новая — «Программа» → запуск, браузер |
| `site.cmd start` / `stop` | запустить (и открыть браузер) / остановить |
| `site.cmd rollback` | вернуть «Программа.прежняя»; база не меняется |
| `site.cmd autostart` | ярлык в «Автозагрузке»: сайт запускается при входе в Windows (без прав администратора) |

Сайт работает **без окна** (журнал — в файле, `Журнал\site-ГГГГ-ММ.log`); остановить — `site.cmd stop`. Раньше было свёрнутое окно — его принимали за забытую командную строку и закрывали, сайт останавливался (12.10.2026; поймано `Services\ExitWatch.cs`: в журнал пишется, почему сайт завершился — окно закрыто, выход из Windows, сбой; `Site.ps1` пишет туда же о своей остановке; раз в час — «Копия базы сделана», видно, до какого часа сайт работал). `Site.ps1` запускает сайт через WMI (`Win32_Process.Create`), а не `Start-Process`: сайт не дочерний процесс запустившего — Claude Code держит свои команды в «задании» Windows, запущенный оттуда сайт закрылся бы вместе с ним. `site.cmd autostart` — ярлык в «Автозагрузке», тоже без окна. После выключения компьютера без автозапуска сайт сам не поднимается.

**Где что** (`%LocalAppData%\RAS_v_2.0\RAS-Clash Analysis\Site`): `Программа\` — программа сайта (заменяется при обновлении, с ней `appsettings.json`); `settings.json` — свои настройки (тот же вид, что `appsettings.json`, обновление не трогает): `Urls`, раздел `Site` — `DataFolder`, `BackupFolder`, `ScanMinutes`, `HourlyBackups`, `NightlyBackups`; `clashes.db` — база; `Снимки\<номер отчёта>\` — снимки коллизий (копируются при загрузке: в папке отчётов их перезапишет следующий прогон); `Журнал\site-ГГГГ-ММ.log`; `Копии базы\` — копии на этом компьютере. На сервере — `Data\RAS-Clash Analysis\Копии базы\Ежечасно` (48) и `Ежедневно` (60, первая копия дня).

**Устройство:**
- `Data\Database.cs` — база SQLite, шаги устройства базы (`Migrations`, версия — `Meta.Version`; дополнительная работа шага на C# — `MigrationCode`); выпущенный шаг не меняется, изменение — новый шаг; перед переносом — копия базы рядом (`clashes.db.до-версии-N-…`); на время переноса проверка связей выключена, перед записью шага — `PRAGMA foreign_key_check`. Время в базе — местное, «yyyy-MM-dd HH:mm:ss». Шаги: 1 — таблицы; 14 — загрузки отчётов до появления истории — в историю (`RestoreImports`), индекс `SiteLog(Time)`; 13 — `Categories.Color`, `Subcategories.Color`; 12 — `Subcategories`, `CategoryTests.SubcategoryId` (подкатегории); 11 — `Categories`, `CategoryTests` (категории проверок); 10 — `Blocks`, `Projects.ManualBlocks` (блоки вручную); 9 — `SiteLog` (история сайта); 8 — `DeletedReports` (файлы, удалённые кнопкой с сайта; кнопку убрали в тот же день — таблица не используется); 7 — склейка коллизий, разошедшихся из-за переименованной модели (`MergeRenamed`), ключи `ids:`; 6 — `ReportTests` (какие проверки были в отчёте) и «Исправлена: нет в отчёте» — на следующий прогон после последнего появления (`ClashStore.RetimeFixes`; после более раннего отчёта, загруженного позже, — заново); 5 — коллизия = пара элементов (`MergePairs`: объединение коллизий одной пары), `Occurrences.Points`, `Reports.Suspicious`, «Ждёт проверки» → «Исправлена»; 4 — запись «Исправлена: нет в более позднем отчёте» у коллизий из более раннего отчёта; 3 — «Ждёт проверки» (ручные «Исправлена» — к нему), `Clashes.ReturnCount`, свои названия типов `TypeNames(ProjectId, Name, TypeName)`, `Reports.Warning`; 2 — критичность и блок у проверки (`Tests`: уникальна по проекту, критичности, блоку, названию), «личность» уникальна в своей проверке (`Clashes`: `UNIQUE(TestId, IdentityKey)`), у отчёта — критичность, блок, откуда дата (`DateSource`), настройки сайта (`Settings`, пока пустая); у уже загруженного — по пути отчёта (`FillPlaces`).
- Таблицы: `Projects` (название, папка отчётов), `Reports` (файл, его SHA-256, дата отчёта, единицы), `Tests` (проверка проекта, последний отчёт), `Clashes` («личность»: ключ, статус, есть ли в последнем отчёте, впервые / последний раз, последнее появление), `Occurrences` (появление в отчёте: имя, статус Navisworks, снимок, точка, расстояние, оси, группа), `Elements` (два элемента появления), `ReportTests` (проверки отчёта — по ним следующий прогон проверки), `Events` (история: найдена, исправлена — нет в отчёте, снова в отчёте, смена статуса, комментарий).
- `Logic\ReportPath.cs` — папки с отчётами по названиям, в любом порядке вложенности (с тестами `ClashPathTests`): критичность («высок…», «сред…», опечатка «срдн…», «низк…»), блок («S1», «S08» → «S8», русская «С», «Блок / Секция / Корпус N»), дата прогона («08.10.2026», «8.10.26», «2026-10-08», с текстом вокруг); название папки проекта не участвует. Дата отчёта: из отчёта → из папки прогона (+ время файла) → время файла.
- `Logic\ReportMerge.cs` — новый отчёт против известного (без базы, с тестами `ClashMergeTests`): правила — в `DECISIONS.md` («Коллизии: пара элементов, три статуса»). Коллизия — пара элементов в проверке (`ClashRules.IdentityKey`, порядок не важен; номер Navisworks — только при неполной паре); результаты одной пары — одна коллизия с числом точек (`MergeStep.Points`); предохранитель `TooManyGone`.
- `Logic\RunCheck.cs` — проверки без отчёта в последнем прогоне своего блока и критичности (с тестами): предупреждение над списком и строки «Нет отчёта» в «Отчётах» (`Project.razor`, `MissingBox`); статусы не меняются.
- `Logic\ClashFacets.cs` — отборы списка (с тестами `ClashFacetTests`): поля «Уровень», «Категория», «Отчёт» (есть / нет в последнем), «Статус» («Раздел» и коды разделов в именах моделей убраны 14.10.2026 — DECISIONS.md, «Сайт без привычек компании»); у коллизии значения обоих элементов; несколько значений поля — «или», поля между собой — «и»; число у значения — с учётом всех отборов, кроме своего поля; поиск; подпись на кнопке («2 Этаж, 3 Этаж +1»).
- `Services\ReportImporter.cs` — проверка — в своей критичности и своём блоке (`EnsureTest`). Проверка папок: все `*.xml` в папке проекта и подпапках (недоступные пропускаются), кроме папок снимков `…_files`; файл, совпадающий с последним загруженным вариантом того же пути, пропускается; новые — по дате отчёта, каждый — одной транзакцией. Отчёт старше уже загруженного по этой проверке только дополняет историю. Занятый файл — «повторим позже». Модель названа иначе, чем в соседнем прогоне той же коллизии, — предупреждение у отчёта (`RenamedModels`). **Замена отчёта:** тот же файл выгружен заново в тот же день прогона — прежний вариант отменяется (`UndoReport`, `FinishReplace`) и загружается новый; только последний отчёт своих проверок (`LaterRuns`), перед заменой — копия базы `clashes.db.до-замены-отчётов-…` (DECISIONS.md, «Замена отчёта»). **Удаление — по папке:** файла отчёта больше нет в папке — отчёт удаляется и с сайта (`RemoveMissing`, до загрузки новых, от новых к старым, только последний отчёт своих проверок; папка недоступна, пуста или пропало больше половины — ничего не удаляется; DECISIONS.md, «Удаление отчёта — по папке»).
- **Категории проверок** (на весь сайт; «Настройки» → «Категории проверок», `Components\TestCategoriesEditor.razor`; `Categories`, `CategoryTests` — шаг 11 базы; логика — `Logic\TestCategories.cs`, тесты `ClashCategoryTests`): категория — по названию проверки (ключ без регистра и пробелов), проверка — в одной категории и не больше чем в одной её подкатегории (`Subcategories`, шаг 12); проверки — по названию или из XML; цвет категории / подкатегории (палитра из 18, шаг 13) — в списке столбцы «Категория» и «Подкатегория» с метками своего цвета (при открытой карточке — в её сведениях), точкой в «Типе проверки». В проекте — категории заголовками внутри «Типа проверки» боковой панели (пустые — по флажку в «Настройках», `SiteOptions.ShowEmptyCategories`) (`TypeTree`, `ClashFilter.Category`; определяется при показе — `CategoryOf`), по нему — список, отчёты, блоки, типы, «нет отчёта» (DECISIONS.md, «Категории проверок»).
- **Блоки — вручную** (проекты, добавленные с 15.10.2026; `Projects.ManualBlocks`): блок — название и папка внутри папки проекта (`Blocks`, шаг 10 базы; `Logic\ProjectBlocks.cs`, тесты `ClashBlockTests`; форма — `Components\BlocksForm.razor` — при добавлении проекта и в разделе «Проект»). Подсказка — вложенные папки, похожие на блоки. Без блоков отчёты не загружаются; отчёты вне блоков — тоже, их папки — `ReportImporter.OutsideBlocks`, предупреждение на странице и карточке проекта. Удалить — только блок без отчётов. Проекты, добавленные раньше, — с распознаванием по названиям папок (DECISIONS.md, «Блоки — вручную»).
- **Сводка проекта** (раздел «Сводка», `Components\ProjectSummary.razor`; графики — `Components\BarChart.razor`, `LineChart.razor`, `WaterfallChart.razor`, SVG без библиотек; «Изменение количества активных коллизий» между двумя датами — `RunHistory.Change`): у каждой цифры одно место; три страницы подразделами «Сводки» на боковой панели — «Дашборд» (сводно, на выбранную дату: крупные и мелкие плитки с изменением к прошлой дате, тренд коллизий — единственный на сводке, «По категориям» уровнем ниже выбранного — подкатегории раскрываются стрелкой, `ProjectView.SummaryOpenCategories`), «Аналитика» (подробно, вкладки: по проверкам — таблица с категорией и подкатегорией, по блокам — блоки × категории и таблица, динамика — % исправлено по датам, у каждой линии свой цвет, наведение выделяет линию, рекуррентность, качество данных; `ProjectView.SummaryTab`), «Сравнение отчётов» (две даты: итог, проверки с Δ, изменение количества активных — крайние столбики подписаны датами, что изменилось; `ProjectView.SummaryPage`); Excel на каждой странице, «Печать / PDF»; состояние на дату — по отчётам и журналу статусов сайта (`RunHistory.ManualStates`, без служебных записей — `ClashStore.NotSystemEvent`); в отборах боковой панели, деление — уровнем ниже выбранного (категории → подкатегории → типы проверок; `By` в `ProjectSummary`); нажатие — к списку с отборами. Состояние на прошлые прогоны — по отчётам (`Logic\RunHistory.cs`, `ClashStore.RunHistory`; тесты `ClashRunHistoryTests`; DECISIONS.md, «Сводка проекта»).
- **История сайта** (`Data\SiteHistory.cs`, `SiteLog` — шаг 9 базы; лента — `Components\HistoryList.razor`, страница `/history` и раздел «История» проекта): что и когда сделано — отчёты (загрузка по прогонам, замена, удаление, отказы, предупреждения), статусы и комментарии, проекты, настройки, обновления сайта; лента — по времени (`ClashStore.History`), загрузки до появления истории дописаны шагом 14 базы; «кто» (`Author`) — с учётными записями (DECISIONS.md, «История сайта»).
- **Что принёс прогон** (`RunDelta`, `Components\Delta.razor`): новые, исправлены, вернулись и набор проверок — «+N проверок (M коллизий)», «−N проверок» (строка прогона блока в «Отчётах» — против прошлого прогона блока по `ReportTests`; карточка проекта; кнопка «в новых проверках» над списком; DECISIONS.md, «Новые и пропавшие проверки»).
- **Список коллизий — по образцу автора статьи** (DECISIONS.md, «Список коллизий — по образцу автора»): отборы — одной строкой («Критичность» убрана 14.10.2026; «Дата» — `ProjectView.RunDate`: last / день «yyyy-MM-dd» / all; у коллизии — дни прогонов `ClashRow.Runs`: была в отчётах дня или исправлена ими; «Статус» — поле `ClashFacets.State`, по умолчанию активные), заголовок «Коллизии (N)» с прогоном, группировкой и «Excel» (`ras.download`), столбцы Дата · Проверка · Раздел (`ClashFacets.DisciplinePair`) · Имя · Расстояние · Оси · Уровень · Статус · Повторы (`ClashRow.Repeats`) с сортировкой, страницы (`ProjectView.PageSize`; строки и заголовки групп — `ListItem`); карточка — `ClashPanel`: верх закреплён (`.cc-top`: имя, статус, «что с чем», кнопки статуса с клавишами 1/2/3 — `site.js`, комментарий), низ прокручивается (`.cc-body`: сведения без пустых, объекты А и Б, снимок (объекты — выше снимка с 15.10.2026), история); новая коллизия — карточка в начало (`ras.top`). Столбец «Комментарий» (вместо «Что с чем», 15.10.2026) — последний комментарий (`ClashRow.LastComment`, число — `Comments`), элементы — в подсказке; «Расстояние» / «Оси» — только если есть в отчётах; карточка выезжает справа поверх списка, список не меняется (с 15.10.2026; раньше на широком экране необязательные столбцы `.opt` прятались) (DECISIONS.md, «Разбор удобства 13.10.2026»).
- **Статусы — три, как у автора:** «Активная», «Исправлена» (нажали или пропала из полного отчёта своей проверки), «Допущена». Возврат после исправления — `ReturnCount` и событие «вернулась». Пропало подозрительно много — `Reports.Suspicious`, у отчёта «Вернуть активными» (`ClashStore.UndoReportFixes`). Старые события `confirmed` и `rekey` в истории остаются. Отчёт **неполный**, если в файле коллизий меньше «всего» в итоге Navisworks (`ReportMerge.IsComplete`, `ClashTest.ResultsInFile`): пропавшие не трогаются, предупреждение — в `Reports.Warning` и итоге загрузки.

## Подводные камни (известные заранее)

- **Номер элемента (ElementId) из Navisworks** — только номер; постоянного идентификатора (UniqueId) в отчёте нет. Номер уникален только внутри своего файла — элемент ищется по паре «файл модели + номер».
- **Имя файла модели** у локальной копии Revit бывает с припиской пользователя — сравнивать с именем хранилища.
- **Имена файлов `.nwc` — не всегда имена хранилищ.** В образцах: `…_KJ01_01_M3_с лестницей_BIM_Alma.nwc`, `…_VK01_01_М3_отсоединено.nwc` — выгружены из копий; у моделей ОВ и ВК в «М3» буква **кириллическая**, у АР — латинская. Мосту сопоставлять модель с файлом нестрого (начало имени, без различия М/M).
- **Уровни называются по-разному в разных разделах:** у АР — «1 Этаж … 5 Этаж», но «06 Этаж»; у ОВ — «01 Этаж … 06 Этаж». Группировка — `ClashRules.LevelKey` (ведущие нули не различаются).
- **Сайт и проект модуля в одной папке.** Будущий проект модуля (`RASv2.ClashAnalysis.csproj` в корне папки модуля) по умолчанию подхватит все `*.cs` из подпапок — `Site\` из него исключить.
- **Элементы связей** нельзя изолировать по одному средствами Revit — только связь целиком; обрезка 3D-вида строится по габаритам с учётом положения связи.
