# RAS-Clash Analysis — модуль работы с коллизиями

Единая база коллизий компании — по всем проектам и разделам — из отчётов Navisworks Clash Detective: сайт во внутренней сети (список, статусы, комментарии, ответственные, дашборды) и мост в Revit — этот модуль: показ коллизии в открытой модели по кнопке с сайта. Устройство — как в статье «Clash Analytics», с нашими улучшениями (`DECISIONS.md`).
Общие правила плагина — `PRINCIPLES.md` в корне, сборка и выпуск — `CLAUDE.md` в корне. Решения по модулю, планы и идеи — `DECISIONS.md` рядом.

## Зачем и для кого

- **Зачем.** Коллизии ищут в Navisworks, а исправляют в Revit; между ними — отчёты HTML и Excel, мессенджеры, копирование номеров элементов в «Выбор по коду». Нет ни общей картины («сколько коллизий, кто, где, как идёт»), ни удобного пути от коллизии к элементу.
- **Для кого.** Все: BIM-координатор загружает отчёты и раздаёт, проектировщики открывают свои коллизии в Revit и отмечают исправленные, руководители смотрят дашборды.
- Идея и устройство — статья «Clash Analytics» (habr.com/ru/articles/1033602), с нашими улучшениями (`DECISIONS.md`).

## Состояние

Обсуждается: устройство — в `DECISIONS.md` («Единая база коллизий»), пилот и этапы — там же («Пилот, проекты, этапы — уточнения»).

Есть разбор отчётов (`Reports\`, без Revit и без базы — общий для сайта и моста; проверки — `tests\RASv2.Tests\ClashReportTests.cs`):
- `ClashReport.cs` — отчёт как он есть: проверки, коллизии (guid, статус Navisworks, снимок, группа, точка, расстояние, дата обнаружения, оси), элементы (файл модели, уровень, категория, семейство, тип, имя, номер, весь путь);
- `ClashReportReader.cs` — чтение XML; не отчёт или битый файл — `InvalidDataException` с причиной по-русски; коллизия без элементов пропускается с предупреждением; дата отчёта — самая поздняя дата обнаружения, без неё — время файла;
- `ClashRules.cs` — «личность» коллизии (`IdentityKey`: guid, без него — проверка + пара «файл + номер»), уровень для группировки (`LevelKey`), статус Navisworks → наш (`StateOf`), снимок (`ImageFile`), единицы.

Проверено на всех пяти отчётах S08 (143 коллизии): у всех есть номер элемента, файл модели, уровень и снимок.

**Сайт — первая версия пилота (09.10.2026)**, только для разработчика, на его компьютере (`http://localhost:5080`). Проекта модуля в Revit (мост) ещё нет.

## Сайт

Папка `Site\` — проект `RASv2.ClashAnalysis.Site` (ASP.NET Core, .NET 8, страницы — Blazor, обновление страниц через постоянное соединение с сайтом). Разбор отчётов — `..\Reports\*.cs` исходниками. Сборка плагина (`build.cmd`) сайт не собирает; свой запуск — `site.cmd` в корне (`tools\Site.ps1`):

| Команда | Что делает |
|---|---|
| `site.cmd` | проверки → сборка → остановка сайта → копия базы («Копии базы\перед обновлением …», 10 последних) → «Программа» становится «Программа.прежняя», новая — «Программа» → запуск, браузер |
| `site.cmd start` / `stop` | запустить (и открыть браузер) / остановить |
| `site.cmd rollback` | вернуть «Программа.прежняя»; база не меняется |
| `site.cmd autostart` | ярлык в «Автозагрузке»: сайт запускается при входе в Windows (без прав администратора) |

Сайт работает в своём свёрнутом окне (в нём журнал); закрыть окно — остановить сайт. Службой Windows станет при переезде на сервер (нужны права администратора).

**Где что** (`%LocalAppData%\RAS_v_2.0\RAS-Clash Analysis\Site`): `Программа\` — программа сайта (заменяется при обновлении, с ней `appsettings.json`); `settings.json` — свои настройки (тот же вид, что `appsettings.json`, обновление не трогает): `Urls`, раздел `Site` — `DataFolder`, `BackupFolder`, `ScanMinutes`, `HourlyBackups`, `NightlyBackups`; `clashes.db` — база; `Снимки\<номер отчёта>\` — снимки коллизий (копируются при загрузке: в папке отчётов их перезапишет следующий прогон); `Журнал\site-ГГГГ-ММ.log`; `Копии базы\` — копии на этом компьютере. На сервере — `Data\RAS-Clash Analysis\Копии базы\Ежечасно` (48) и `Ежедневно` (60, первая копия дня).

**Устройство:**
- `Data\Database.cs` — база SQLite, шаги устройства базы (`Migrations`, версия — `Meta.Version`); выпущенный шаг не меняется, изменение — новый шаг; перед переносом — копия базы рядом. Время в базе — местное, «yyyy-MM-dd HH:mm:ss».
- Таблицы: `Projects` (название, папка отчётов), `Reports` (файл, его SHA-256, дата отчёта, единицы), `Tests` (проверка проекта, последний отчёт), `Clashes` («личность»: ключ, статус, есть ли в последнем отчёте, впервые / последний раз, последнее появление), `Occurrences` (появление в отчёте: имя, статус Navisworks, снимок, точка, расстояние, оси, группа), `Elements` (два элемента появления), `Events` (история: найдена, исправлена — нет в отчёте, снова в отчёте, смена статуса, комментарий).
- `Logic\ReportMerge.cs` — новый отчёт против известного (без базы, с тестами `ClashMergeTests`): правила — в `DECISIONS.md` («Сайт: первая версия»).
- `Services\ReportImporter.cs` — проверка папок: все `*.xml` в папке проекта и подпапках, кроме папок снимков `…_files`; файл, совпадающий с последним загруженным вариантом того же пути, пропускается; новые — по дате отчёта, каждый — одной транзакцией. Отчёт старше уже загруженного по этой проверке только дополняет историю. Занятый файл — «повторим позже».
- `Services\ImportScheduler.cs` — проверка папок через 10 с после запуска и каждые `ScanMinutes` минут; `BackupService.cs` — копии базы (SQLite `BackupDatabase`, через временный файл); `FileLogger.cs` — журнал.
- `Data\ClashStore.cs` — списки, карточка, смена статуса (одной или многих, с комментарием), комментарии. Поиск — без учёта регистра в C# (`LIKE` в SQLite не различает регистр только у латиницы).
- Страницы (`Components\Pages`): «Проекты» (`/`: строка проекта нажимается целиком, «+ Новый проект» — форма по кнопке, после создания — сразу в проект; проверка папок, состояние копий базы); «Проект» (`/project/{id}`, вкладки «Коллизии», «Проверки» — щелчок по проверке показывает её коллизии, «Отчёты», «Проект» — название и папка); «Коллизия» (`/clash/{id}`, отдельная страница той же карточки). Снимок — `/snimok/{номер появления}`, только из папки снимков.
- **«Коллизии» — список и карточка рядом** (разбор коллизий подряд, без ухода со страницы): статус — нажимаемые счётчики «Активные / Исправлены / Допущены / Все» (числа — при текущем отборе); отбор по проверке, уровню, категории, поиск (ждёт паузу в наборе, 300 мс), «только из последних отчётов»; сортировка щелчком по заголовку; строки в один этаж, длинное — с подсказкой; 300 строк и «Показать ещё». Щелчок по строке — карточка справа (`ClashPanel`, список при этом без «Проверки» и «Впервые»); ↑ ↓ — соседняя коллизия, Esc — закрыть; «после статуса — к следующей» (включено). Флажки — смена статуса многим, больше 10 — с вопросом; итог — строкой «изменено N из M». Отбор, сортировка, выбор и вкладка помнятся, пока открыта вкладка браузера (`ProjectViewState`, на соединение): ушёл в отдельную карточку и вернулся — всё на месте; F5 — заново.
- **Карточка** (`Components\ClashPanel.razor`, узкая — справа от списка, широкая — отдельная страница): статус кнопками (текущий — залит), комментарий (к смене статуса или сам по себе, Ctrl+Enter), элементы — категория · тип, модель · уровень, номер и «Копировать номер» (для «Выбор по коду» в Revit; `wwwroot\site.js`: буфер обмена, на адресе не `localhost` — запасной способ), снимок, история; «Подробнее» — расстояние, оси, группа, статус Navisworks, наборы, семейство и имя, точка Navisworks, появления в отчётах.
- Адреса стилей и скрипта — с меткой версии (`AppVersion`): после обновления сайта браузер не берёт старые из кэша.
- Оформление — `wwwroot\site.css`: цвета — переменные, светлая и тёмная тема по системе. Обрыв связи с сайтом — своё окно по-русски (`components-reconnect-modal` в `App.razor`).

**Проверено без Revit (09.10.2026, на копии отчётов S08 во временной папке):** загрузка 5 отчётов (143 коллизии, снимки, история), страницы открываются; второй прогон: убранная коллизия — «Исправлена» («Нет в отчёте»), помеченная в Navisworks «Исправлено» — «Исправлена», остальные — без изменений; возвращённая — снова «Активная»; копии базы (цельные); `site.cmd`: установка, обновление с копией базы, откат, остановка.

**Проверено в браузере без человека (09.10.2026, Edge без окна, Selenium, данные S08):** выбор строки и карточка, ↑ ↓, смена статуса в карточке и переход к следующей, «Копировать номер», вопрос перед сменой статуса у многих, сортировка, пустой результат и «Показать все», возврат из отдельной карточки с сохранённым отбором, светлая и тёмная тема.

**Ещё не проверено человеком:** удобство на настоящей работе; комментарии; окно «связь прервалась» при перезапуске сайта; копия базы на сервер; узкое окно (меньше 1100 точек — карточка под списком).

## Версии Revit

2023 и 2026 — сразу (разбор отчётов — System.Xml, без System.Text.Json).

## Источник — отчёты Navisworks (XML)

Navisworks Manage 2023, Clash Detective → «Отчёт» → формат XML. Один файл — одна проверка (например, «КЖ Вертикальные конструкции / МЕР Воздуховоды»), рядом папка `<отчёт>_files` со снимками коллизий (`cd040001.jpg`…). Образец — `C:\Users\user\Desktop\Aport\Высокая\S08\XML` (5 отчётов, 143 коллизии, 15.09.2026).

Что в XML (`exchange/batchtest/clashtests/clashtest`):

| Где | Что |
|---|---|
| `clashtest@name`, `@test_type`, `@tolerance` | проверка: «КЖ Вертикальные конструкции/МЕР Воздуховоды», `hard`, допуск в метрах |
| `clashtest/left|right/clashselection/locator` | наборы, которые сравнивались |
| `clashtest/summary` | итог: всего, новые, активные, проверенные, подтверждённые, исправленные |
| `clashresult@name`, `@guid`, `@status`, `@href` | коллизия: «Конфликт1», постоянный номер Navisworks, статус (`new`, `active`, `reviewed`, `approved`, `resolved`), снимок |
| `clashresult/clashpoint/pos3f` | точка пересечения (в единицах `units`, координаты Navisworks) |
| `clashobject/pathlink/node` | путь элемента: «Файл», «Файл», **файл модели `.nwc`**, **уровень**, **категория**, семейство, тип… (9 или 11 узлов) |
| `clashobject/smarttags` | «Элемент Имя» и **«Объект Id» — номер элемента в Revit** |

Файл `.nwc` назван как модель Revit (`3457_01_01_S8_AR01_01_M3.nwc` ↔ `3457_01_01_S8_AR01_01_M3.rvt`) — по нему находится, в открытой модели элемент или в её связи.

В образцах нет даты обнаружения, глубины пересечения и осей — их можно включить в настройках отчёта Navisworks (рекомендуется, `DECISIONS.md`). Их форма в XML (`createddate/date@year…`, `clashresult@distance`, `gridlocation`) и группы коллизий (`clashgroup`) — по описанию формата, на настоящем отчёте ещё не проверены. Английский Navisworks: «Element ID», «Item Name» — тоже читаются.

## Подводные камни (известные заранее)

- **Номер элемента (ElementId) из Navisworks** — только номер; постоянного идентификатора (UniqueId) в отчёте нет. Номер уникален только внутри своего файла — элемент ищется по паре «файл модели + номер».
- **Имя файла модели** у локальной копии Revit бывает с припиской пользователя — сравнивать с именем хранилища.
- **Имена файлов `.nwc` — не всегда имена хранилищ.** В образцах: `…_KJ01_01_M3_с лестницей_BIM_Alma.nwc`, `…_VK01_01_М3_отсоединено.nwc` — выгружены из копий; у моделей ОВ и ВК в «М3» буква **кириллическая**, у АР — латинская. Мосту сопоставлять модель с файлом нестрого (начало имени, без различия М/M).
- **Уровни называются по-разному в разных разделах:** у АР — «1 Этаж … 5 Этаж», но «06 Этаж»; у ОВ — «01 Этаж … 06 Этаж». Группировка — `ClashRules.LevelKey` (ведущие нули не различаются).
- **Сайт и проект модуля в одной папке.** Будущий проект модуля (`RASv2.ClashAnalysis.csproj` в корне папки модуля) по умолчанию подхватит все `*.cs` из подпапок — `Site\` из него исключить.
- **Элементы связей** нельзя изолировать по одному средствами Revit — только связь целиком; обрезка 3D-вида строится по габаритам с учётом положения связи.
