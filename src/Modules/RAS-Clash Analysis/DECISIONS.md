**В Revit** — модуль RAS-Clash Analysis (первая часть модуля в плагине; Revit 2023 и 2026), слушает только `127.0.0.1`, без прав администратора; у сайта и моста — номер версии договорённости (PRINCIPLES.md, раздел 10: прежние сборки модуля продолжают работать).
1. Проверить: открыты ли модель и связи коллизии (файл модели из отчёта — `….nwc` — сопоставляется с открытой моделью или связью без расширения и приписки локальной копии; логика — отдельно, с тестами), есть ли в них оба элемента (номер элемента; у связи — с её положением).
2. Открыть **личный вид** пользователя: связи, которые в коллизии не участвуют, в нём **скрыты самим плагином** (встречное предложение принято — вместо предупреждения «скройте связь»; рабочие виды не трогаются). Следующая коллизия — тот же вид перестраивается.
3. **Вид удаляется, когда закрыли его вкладку**; оставшийся после сбоя — при следующем открытии модели. Поведение — как у вида изменений RAS-Model History, но **код свой** (разработчик: «не надо использовать код как там — я привёл для примера»; ядро не меняется).

**Предупреждения** (отключаются в настройках): нужная связь выгружена; нужной связи нет в модели. Не отключаются — показать нельзя: не открыта ни одна модель коллизии; элемента с таким номером нет.

**Кнопка «Настройки вида» на ленте** — настройки **личные**:
- **тип вида:** 3D (обрезка рамкой вокруг пары), план (свой план: уровень — ближайший ниже точки коллизии, секущая плоскость — на высоте коллизии, обрезка вокруг пары), разрез (через точку коллизии, у стены — поперёк стены, иначе — по короткой стороне пары; глубина — только вокруг элементов), **«Авто»**: плита, перекрытие, фундаментная плита — план; стена — разрез; остальное (в том числе потолки и крыши) — 3D;
- **показ:** с обрезкой или изолировать;
- **обрезка:** запас N м или по размеру элементов;
- **стиль:** классические стили Revit;
- **«Красить элементы»** — цвета стандартные, как в Navisworks (первый элемент — красный, второй — зелёный), без выбора цвета; **элемент связи — тоже** (разработчик);
- галочки предупреждений.
- **По умолчанию:** 3D, обрезка по размеру элементов, «Тонированный», красить — да, изолировать — нет, предупреждения — включены.

**Покраска элемента связи — проверить первым в прототипе.** Revit API перекрашивает только элементы самой модели, элемент внутри связи — нет. Путь без изменения модели — **рисовать краску поверх** (DirectContext3D: временное изображение в виде, не в модели, не сохраняется и не синхронизируется): форма элемента (у связи — с её положением) в нашем виде, красным или зелёным; так же — и элемент самой модели, чтобы выглядели одинаково. Это объёмная форма — при повороте 3D-вида выглядит как покрашенный элемент с любой стороны. Проверить: мерцание там, где краска совпадает с поверхностью элемента (рисовать на 1–2 мм больше), обрезается ли рамкой 3D-вида, рисуется ли на плане и разрезе. Если где-то видно «бутафорию» — сказать разработчику.

**Отвергли / не нужно:** вид без своего (временная изоляция в текущем 3D — вариант Б: без обрезки); выбор вида на сайте у кнопки; выбор цветов покраски; предупреждение «скройте лишнюю связь» (связи скрывает сам плагин); выбор экземпляра связи, вставленной дважды (разработчик: «у нас такого быть не может»).

**Не в первой версии:** показ нескольких коллизий из списка сразу; запоминание постоянного идентификатора элемента (UniqueId); кнопка «Открыть сайт» на ленте; сайт для коллег (адрес сервера).

**Как работает** (`ReportImporter`):

- в одной транзакции: `UndoReport` убирает появления и записи истории прежнего варианта, у затронутых коллизий — состояние до него (последняя оставшаяся смена статуса, в том числе ручная; «вернулась» — минус к числу возвратов), у проверок — прежний последний отчёт; коллизии, найденные прежним вариантом, «ждут» новый: есть в нём — та же коллизия (история и комментарии сохраняются, «Найдена» — у нового отчёта, ручной статус сохраняется), нет — удаляются (`FinishReplace`); проверки без отчётов и коллизий (опечатка в названии, исправленная новой выгрузкой) — удаляются; снимки прежнего варианта — тоже. Предохранитель «исправлены сразу» не считает «ждущие» коллизии.

### Новые и пропавшие проверки — в «что принёс прогон» (14.10.2026)

**Повод.** Разработчик загрузил 01.10, потом 08.10: активных было 1634, стало 1689, а в строке прогона — «+6 новых · 133 исправлено». Не сходилось: в 08.10 впервые появились 3 проверки (182 коллизии; их коллизии — активные, но не «новые»: их просто впервые проверили) и пропали 2. Набор отчётов при этом почти тот же (101 → 102), поэтому было непонятно, откуда разница.

**Решение.** Набор проверок — часть «что принёс прогон» (`RunDelta.NewTests`, `NewTestClashes`, `DroppedTests`; `Delta.razor`):
- строка прогона блока в «Отчётах» — «+N проверок (M коллизий)» и «−N проверок» (названия — в подсказке); по проверкам отчёта (`ReportRow.TestIds`, `NewTestIds` — из `ReportTests`) против прошлого прогона блока; в первом прогоне блока — по-прежнему «первая проверка»;

- над списком коллизий — кнопка «+N в новых проверках» рядом с «новых / исправлено / вернулось» (показывает именно их);
- в «⚠ Нет отчёта» — если проверка пропала именно в этом прогоне, а в блоке появилась новая: «если это она же, переименованная, её коллизии посчитаны дважды — верните прежнее название в Navisworks».
Теперь «активных было − исправлено + новые + в новых проверках = активных стало» читается на экране.

**Поправка к регламенту (моя ошибка 14.10.2026):** переименованная проверка не делает коллизии «исправленными» — прежняя остаётся с «нет отчёта» и её коллизии висят активными, а коллизии новой считаются ещё раз (вдвойне). Текст регламента исправлен.

2. **Работа команды.** Отчёты загружаются в общую папку проекта на сервере (`Data\RAS-Clash Analysis`), у коллизии — свои статусы («Активная / Исправлена / Допущена»), комментарии, назначение отделу или человеку, история действий; сравнение отчётов между датами.
3. **Связь с журналом изменений.** Кто и когда создал коллизию (последняя правка элемента перед отчётом), ответственный — по тому, кто менял элементы, «вероятно, исправлена» — элемент изменён или удалён после отчёта.
4. **Дашборды** для руководителей — отчёт HTML по расписанию (тот же, что задуман для аналитики RAS-Model History): проекты, разделы, уровни, динамика, повторяемость.

**Почему так, а не как в статье** (сервис Clash Analytics, habr.com/ru/articles/1033602):
- ~~Без веб-сервера~~ — заменено решением «Плагин + сайт во внутренней сети» выше. Остаётся: без моста `127.0.0.1`; данные — в общей папке на сервере (как журналы изменений); плагин обновляется нашим загрузчиком.
- **Связь с журналом изменений** (этап 3) — у статьи её нет: видно, кто создал коллизию, и исправление замечается до нового прогона Navisworks.
- **Коллизия узнаётся** по постоянному номеру Navisworks (`clashresult@guid` — сохраняется между прогонами одной проверки), запасной вариант — проверка + пара «файл модели + номер элемента». Постоянный идентификатор элемента Revit (UniqueId) запоминается при первом показе — номер элемента из отчёта бывает нестабилен.
- **Статусы и комментарии** каждый пишет в свои файлы (как журнал изменений) — одновременная работа многих людей с общей папкой безопасна.

**Отвергли.** Веб-сервис (нужен свой сервер и сопровождение); проверку коллизий средствами самого Revit вместо Navisworks (медленно на больших моделях; в компании уже принят Navisworks) — может стать идеей на потом.

**Рекомендация к отчётам Navisworks.** Включить в настройках отчёта: дату обнаружения, расстояние (глубину пересечения), расположение по сетке осей, описание элементов — для аналитики.
