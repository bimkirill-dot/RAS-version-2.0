# RAS-Clash Analysis — решения и идеи

Что решили по модулю, почему так и что отвергли; планы и идеи. Как вести файл — как `DECISIONS.md` других модулей (PRINCIPLES.md, раздел 14).

## Запланировано

### Блоки — вручную (15.10.2026)

**Видение разработчика** (принято с его поправками): при добавлении проекта — папка проекта, название (из папки, можно поменять) и **блоки**: строки «название на сайте + папка блока» (внутри папки проекта; «Обзор…»; название — из папки, можно вписать своё), плюсик — добавить, корзина — убрать. Блоки можно не добавлять сразу — тогда в проекте везде предупреждение «Добавьте блоки в разделе „Проект“», и там же — та же форма.
- **Блок — папка внутри папки проекта** (путь относительно неё). Сейчас у RAS блоки повторяются внутри каждого прогона (`<проект>\08.10.2026\…\S1`) — так блок папкой не задать; **разработчик поговорит с руководством о новом регламенте названий** (предложение — блок наверху: `<проект>\S1\14.10.2026\…`).
- **Распознавание по названиям — только подсказка:** выбрали папку проекта — её вложенные папки, похожие на блоки (S1, «Блок 2»), сами встают в список; лишнее — корзиной (моё предложение; отдельной галочки «распознавать» нет).
- **Без блоков отчёты не загружаются — даже если блок один** (решение разработчика). Отчёты в папках вне блоков — тоже не загружаются; на странице проекта и на карточке — предупреждение с этими папками («папки вне блоков: S10»), в «Проекте» — кнопки «+ S10» (добавить блок с этой папкой). Отвергли: загружать их в «Без блока» — раз загруженное не переносится, остались бы там навсегда.
- **Уже загруженное при смене блоков не переносится** (решение разработчика). Переименования блоков не будет (решение разработчика: с новой организацией папок оно не нужно) — его нет; удалить можно только блок, из которого ещё ничего не загружено.
- **Проекты, добавленные раньше** (ArmanQala, Zamon), — по-прежнему с распознаванием блоков по названиям папок (`Projects.ManualBlocks = 0`).

**Окно «Добавить проект»** (образец разработчика, 15.10.2026, с моими доработками): своё окно, слева — папка проекта («Обзор…») и название, справа — «Список блоков (N)» с «+ Блок» и блоками карточками (заголовок — имя блока, пока пусто — «Блок N»; папка блока с «Обзор…», затем имя на сайте; у подставленных — метка «найден в папке»; корзина); внизу — «Отмена» и «Добавить и загрузить отчёты», сверху — ✕; прокручивается только колонка блоков; высота окна постоянная — под три карточки блоков, больше — прокрутка (просьба разработчика); на узком экране колонки одна под другой. Карточки блоков — такие же в разделе «Проект». Папки вне блоков после перезапуска сайта находятся сразу (просмотр папки), а не только после проверки папок.
- **Главная (15.10.2026, просьба разработчика):** «+ Добавить проект» и «Проверить папки сейчас» — значками «+» и «обновить» у заголовка «Проекты» (подпись у стрелки — просто «Обновить», просьба разработчика); строка о копии базы внизу убрана — она в «Настройках» → «Копии базы», а если копия не удалась — красная точка на ⚙ в шапке. Вид проектов — **панелями или списком** (переключатель справа от заголовка; список — проект, последний отчёт, последний прогон, активные, исправлены, «исправлено %», предупреждения о блоках; выбор запоминается в браузере — удобство одного зрителя).
- **«Обзор…» убран отовсюду** (15.10.2026, решение разработчика): у папки проекта, у папок блоков и в «Настройках» у папки копий базы — только вставка пути из адресной строки проводника (кавычки «Копировать как путь» снимаются; полный путь к папке блока сокращается до части внутри папки проекта). Своё окно выбора папки (`FolderPicker`) разработчику было непонятно; настоящее окно Windows сайт открыть не может: браузер отдаёт сайту содержимое файлов, а не путь, и окно открывается только на `https://` или `localhost`, а сайт нужен коллегам по сети. Обходной путь — окно Windows и поиск выбранной папки по имени в знакомых местах — разработчик отклонил: «просто вставить путь».

**Устройство:** база, шаг 10 — `Blocks(ProjectId, Name, Folder)`, `Projects.ManualBlocks`; логика — `Logic\ProjectBlocks.cs` (папка блока относительно проекта, блок отчёта — самая глубокая подходящая папка, папка вне блоков, подсказка, проверка списка: пустое, повторы, вложенные папки; тесты `ClashBlockTests`); форма — `Components\BlocksForm.razor`; загрузчик — блок отчёта из папок блоков (`ReportImporter`, `OutsideBlocks`); добавление и удаление блоков — в истории сайта.

**Состояние:** сделано; проверки логики (2023, 2026); в браузере на пробной раскладке «блок наверху» (S1, S2, «Корпус Б»): подсказка S1 и S2, корзина, загрузка только из блоков, предупреждение о папках вне блоков, добавление блоков в «Проекте» (отчёты загрузились), повтор папки — отказ, проект без блоков — ничего не загружено, предупреждение и на карточке; старый проект — как раньше.

### История сайта: что и когда сделано (15.10.2026)

**Мысль разработчика:** история сайта — сначала без пользователей, просто что и когда сделано; когда сайт распространится — с тем, кто сделал. Набросок принят без изменений.
- **Где:** страница «История» (значок часов в шапке, `/history`) — все проекты, отбор по виду действия (Отчёты / Коллизии / Проекты / Сайт), по проекту и поиск; раздел «История» в боковой панели проекта — только он. Новые сверху, по дням; у записи о коллизии — «открыть». Общая лента — `Components\HistoryList.razor`.
- **Что пишется** (`Data\SiteHistory.cs`, таблица `SiteLog`, шаг 9 базы): загрузка отчётов — одной строкой на прогон блока («S1 · 14.10.2026: загружено 11 отчётов — +3 новых · 2 исправлены · +1 проверка (4 коллизии)», «первая проверка», «более ранний прогон»), замена отчёта, удаление по папке, отказы (та же причина при каждой проверке папки — одна запись; «файл занят» — нет), предупреждения; смена статуса вручную (массовая — одной строкой «12 коллизий»), комментарии, «Вернуть активными»; проект добавлен / изменён (что именно) / удалён; настройки сайта (что поменялось); сайт обновлён (дата программы, перенос базы). Проверки папки без изменений — не пишутся.
- **Устройство:** у записи — проект и коллизия без ссылок на таблицы: запись остаётся после их удаления (название проекта запоминается); при удалении проекта или коллизии ссылки в истории обнуляются — номера в SQLite могут достаться новым. Сбой записи истории загрузку не ломает (в журнал).
- **«Кто»** — столбец `Author`, пока пустой; с учётными записями — Windows-логин, в ленте появится столбец «Кто». Хранится бессрочно.

**Состояние:** сделано; проверено в браузере на копии отчётов ArmanQala (перенос базы, загрузка, замена, удаление по папке, отказ — одна запись на две проверки папки, статус и комментарий, переименование проекта, настройки; обе темы).

### Удаление отчёта — по папке: файла нет — нет и на сайте (15.10.2026)

**Решение разработчика:** кнопки удаления на сайте убрать; удаление — как замена: удалили файл из папки — отчёт удаляется и с сайта. Правило одно: что в папке, то и на сайте.
- При проверке папки (`ReportImporter.RemoveMissing`, до загрузки новых): отчёты проекта, файлов которых в папке больше нет, удаляются так же, как при замене (`UndoReport` + `FinishReplace`, без нового отчёта), по одному, от новых к старым — так удаляются и несколько прогонов подряд; перед первым удалением — копия базы (одна на проверку папок, `clashes.db.до-удаления-отчётов-…`).
- Только последний отчёт своих проверок (`LaterRuns`): файл из середины удалён — отчёт остаётся, в итоге проверки папки — почему.
- **Защита от недоступной папки** (моё предложение — раньше я отговаривал удалять вслед за папкой как раз из-за этого риска): папки нет, в ней не найдено ни одного отчёта или пропало больше половины отчётов проекта — ничего не удаляется, в итоге проверки — «похоже, папка недоступна или её переложили»; удалить проект целиком — «Удалить проект». Отчёты не из текущей папки проекта (папку проекта сменили) не трогаются.
- Итог проверки папки: «загружено — N, удалено (файлов нет в папке) — M».
- Таблица `DeletedReports` (шаг 8 базы) больше не используется: выпущенный шаг не меняется, таблица остаётся пустой; файлы, удалённые кнопкой раньше и лежащие в папке, при первой проверке загрузились снова.

**Состояние:** сделано; проверено в браузере на копии отчётов ArmanQala: прогон 15.10 убран из папки — удалён с сайта; S8 за 01.10 и 08.10 убраны разом — удалены по порядку; «0 МЕР…» за 01.10 (проверки нет в 08.10) — удалён; отчёт S1 за 01.10 с продолжением в 08.10 — оставлен с объяснением; убран весь 08.10 (больше половины) — ничего не удалено; ссылки в базе целы.

### ~~Удаление отчёта с сайта~~ (15.10.2026) — заменено в тот же день: кнопки убраны, удаление — по папке (выше)

**Решение разработчика:** кроме замены (ниже) — и ручное удаление: отчёт или прогон бывает просто не нужен (лишняя проверка, не тот проект), а удалённые из папки файлы на сайте остаются.
- В «Отчётах»: «Удалить» у отчёта и «Удалить прогон» у последнего прогона блока — тихие ссылки, видны при наведении на строку; только последние отчёты своих проверок (`ReportRow.Latest`; та же проверка, что и при замене, `LaterRuns`).
- Окно подтверждения с цифрами (`ClashStore.DeletionPreview`): сколько коллизий найдено только в этих отчётах — удалятся (и сколько у них комментариев), сколько исправленных ими снова «Активная», сколько вернувшихся снова «Исправлена»; ручные статусы сохраняются.
- `ReportImporter.DeleteReportsAsync` — под замком загрузки, копия базы `clashes.db.до-удаления-отчётов-…`, в одной транзакции то же, что при замене (`UndoReport` + `FinishReplace`), только без нового отчёта; снимки — после.
- Удалённые файлы — в базе (шаг 8, `DeletedReports`: путь + содержимое): проверка папки их пропускает, пока их не выгрузят заново (другое содержимое — загрузится). Под отчётами — «Удалены с сайта: N» с «Загрузить снова».

**Состояние:** сделано; проверено в браузере на копии отчётов ArmanQala: один отчёт и остаток прогона S9 15.10 (проверка папки их не загрузила, кнопка перешла к 08.10, «Загрузить снова» вернула файл), прогон S7 08.10 (в окне — 179 удалятся, 114 снова «Активная»; активных 1689 → 1624, в S7 остался 01.10 — «первая проверка»); ссылки в базе целы.

### Замена отчёта: выгрузили заново в ту же папку прогона (15.10.2026)

**Повод.** Нужен способ убрать неправильно выгруженный отчёт. Я предложил кнопки «Удалить прогон / отчёт» с окном подтверждения и списком удалённых файлов (иначе проверка папки загрузила бы их снова). **Решение разработчика — проще:** кнопок нет, неправильный отчёт просто выгружают заново поверх, и сайт сам подтягивает новый.

**Как работает** (`ReportImporter`):
- изменённый файл по тому же пути и **тот же день прогона** (у разработчика день — из названия папки прогона) — **замена** прежнего варианта; день позже (отчёт перезаписали без папок с датами) — новый прогон, как раньше;
- заменить можно только **последний отчёт своих проверок** (`LaterRuns`): после него уже есть более поздние прогоны — отчёт не загружается, в итоге проверки папки — почему («удалите проект и добавьте заново»). Отмена отчёта из середины потребовала бы заново проиграть всю историю блока вместе с ручными статусами — не делали;
- перед заменой — копия базы рядом с ней (`clashes.db.до-замены-отчётов-…`, одна на проверку папок);
- в одной транзакции: `UndoReport` убирает появления и записи истории прежнего варианта, у затронутых коллизий — состояние до него (последняя оставшаяся смена статуса, в том числе ручная; «вернулась» — минус к числу возвратов), у проверок — прежний последний отчёт; коллизии, найденные прежним вариантом, «ждут» новый: есть в нём — та же коллизия (история и комментарии сохраняются, «Найдена» — у нового отчёта, ручной статус сохраняется), нет — удаляются (`FinishReplace`); проверки без отчётов и коллизий (опечатка в названии, исправленная новой выгрузкой) — удаляются; снимки прежнего варианта — тоже. Предохранитель «исправлены сразу» не считает «ждущие» коллизии.

**Состояние:** сделано; проверено на копии отчётов ArmanQala (01.10, 08.10 и пробный прогон 15.10): исправленное название проверки (ошибочная проверка и её 12 коллизий ушли, комментарий у другой коллизии на месте), отчёт без двух пар (1 пара целиком — «Исправлена», у другой осталась точка — активна) и обратно полный (исправление отменено), изменённый отчёт 08.10 при уже загруженном 15.10 — не загружен, с объяснением; ссылки в базе целы.

### Пустые отчёты не удалять; ошибочный прогон S7 ArmanQala (15.10.2026)

**Узнали от разработчика.** В компании было правило: отчёт без коллизий удалять. Отсюда почти все «нет отчёта»: в ArmanQala проверка S9 «КЖ Вертикальные конструкции/МЕР Воздуховоды» (1 коллизия на 01.10) в 08.10 пропала — скорее всего, отчёт стал пустым и его удалили, то есть коллизию исправили, а сайт держит её активной. Вероятно, то же в 2025_Zamon (9 проверок без отчёта, 136 «висящих» коллизий, «Коллизии: пара элементов…» выше).

**Решение разработчика:** правило отменить — с сайтом оно не нужно и отнимает время. В регламенте: «пустые отчёты не удалять». Решение «Нет отчёта в прогоне» (статусы не меняются) остаётся: без отчёта сайт по-прежнему не знает, исправлено ли.

**`_МГН` в S7 ArmanQala, 01.10** — та же модель АР, только неправильно названа (разработчик; моё предположение «другая модель, исправления ненастоящие» — неверно). Это переименование: коллизии с теми же элементами сайт склеил (шаг 7). 103 исправления S7 «АР Стены/МЕР Воздуховоды» в 08.10 — по отчётам настоящие: этих пар элементов в 08.10 нет (121 результат → 20); исправили или перечертили (новые номера) — по отчётам Navisworks не различить. «Вернуть активными» не нужно.

**Уже загруженное по старому правилу не исправляем** (решение разработчика): коллизия проверки без отчёта станет «Исправлена» сама — в первом прогоне, где по этой проверке будет отчёт (хоть пустой) и её там нет; день исправления — этот прогон, а не настоящий.

### Новые и пропавшие проверки — в «что принёс прогон» (14.10.2026)

**Повод.** Разработчик загрузил 01.10, потом 08.10: активных было 1634, стало 1689, а в строке прогона — «+6 новых · 133 исправлено». Не сходилось: в 08.10 впервые появились 3 проверки (182 коллизии; их коллизии — активные, но не «новые»: их просто впервые проверили) и пропали 2. Набор отчётов при этом почти тот же (101 → 102), поэтому было непонятно, откуда разница.

**Решение.** Набор проверок — часть «что принёс прогон» (`RunDelta.NewTests`, `NewTestClashes`, `DroppedTests`; `Delta.razor`):
- строка прогона блока в «Отчётах» — «+N проверок (M коллизий)» и «−N проверок» (названия — в подсказке); по проверкам отчёта (`ReportRow.TestIds`, `NewTestIds` — из `ReportTests`) против прошлого прогона блока; в первом прогоне блока — по-прежнему «первая проверка»;
- карточка проекта — «+N проверок (M коллизий)» за последний прогон каждого блока;
- над списком коллизий — кнопка «+N в новых проверках» рядом с «новых / исправлено / вернулось» (показывает именно их);
- в «⚠ Нет отчёта» — если проверка пропала именно в этом прогоне, а в блоке появилась новая: «если это она же, переименованная, её коллизии посчитаны дважды — верните прежнее название в Navisworks».
Теперь «активных было − исправлено + новые + в новых проверках = активных стало» читается на экране.

**Поправка к регламенту (моя ошибка 14.10.2026):** переименованная проверка не делает коллизии «исправленными» — прежняя остаётся с «нет отчёта» и её коллизии висят активными, а коллизии новой считаются ещё раз (вдвойне). Текст регламента исправлен.

**Состояние:** сделано; проверено в браузере на копии отчётов ArmanQala 01.10 и 08.10 и пробном прогоне 15.10 с переименованной проверкой.
