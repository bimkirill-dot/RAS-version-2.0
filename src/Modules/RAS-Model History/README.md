# RAS-Model History — журнал изменений модели для Revit 2026

Плагин ведёт журнал: **кто, что и когда создал, изменил или удалил** в модели. Он охватывает не только элементы, но и виды, шаблоны видов, листы, спецификации, типы, семейства, фильтры, материалы, уровни, оси и настройки проекта. Для изменённых параметров показывает значения **«было → стало»**.

## Возможности

- **Журнал в реальном времени.** Фиксируется каждая транзакция Revit, включая отмену (Undo), повтор (Redo) и откат группы. По каждой записи видны: время, автор, компьютер, команда Revit (например, «Перемещение» или «Изменение типа»), категория, тип объекта, имя, семейство и тип, ID, уровень, рабочий набор и вид-владелец.
- **Параметры «было → стало».** Показываются все параметры из палитры свойств. Дополнительно отслеживаются:
  - имя и тип элемента;
  - положение и поворот (перемещения видны в мм). У элементов без точки вставки и оси (арматура, перекрытия, крыши, лестницы, ограждения) вместо положения запоминаются габариты: сдвиг виден как «[Габариты, мм]»;
  - для видов и шаблонов — фильтры вида и скрытые категории.
- **Удалённые элементы.** Плагин заранее запоминает все элементы модели и их параметры. Поэтому после удаления видно, что именно удалили и кто, и можно вывести значение любого параметра удалённого элемента.
  - **Удалён вместе с …** Если Revit удалил элемент не сам по себе, а вместе с тем, от чего он зависел (марку — со стеной, проём — с перекрытием, арматуру — с балкой, экземпляры — с удалённым типом), в «Что изменилось» написано «Удалён вместе с: Стены · Базовая стена». Это ссылка: щелчок переносит к строке удаления самой стены.
  - Выделенное в Revit запоминается сразу, вместе со всем, что от него зависит, — поэтому даже удалённое сразу после первого открытия модели известно. Если модуль всё же не успел запомнить элемент («нет сведений»), имя, категория и тип берутся из прежних записей журнала об этом элементе (в подробностях — «Сведения: из прежних записей журнала»).
- **Отсоединённые модели журнал не ведёт** — ни на файловом сервере, ни на Revit Server: правки отсоединённой копии не попадают в журнал основной модели. В журнале — надпись «Модель отсоединена от хранилища — журнал не ведётся». Если отсоединённую копию сохранили хранилищем или новым файлом, журнал начинается с этого момента, первой записью — событие «Хранилище создано из отсоединённой копии».
- **Командная история.** Все пишут журналы в одну общую сетевую папку, и панель собирает историю всей команды.
- **Изменения коллег без плагина.** Если плагин стоит не у всех, после синхронизации или обновления из файла-хранилища плагин определяет, какие элементы изменили другие. Автора он берёт из данных совместной работы Revit (кто последним синхронизировал изменение).
- **Сведения о выделенном элементе.** Для элемента, выделенного в Revit, в подробностях панели показывается: кто его создал, кто последним синхронизировал изменение, кто сейчас его занимает, и сколько записей о нём есть в журнале.
- **Фильтры:** поиск (по имени, ID, категории, команде, параметру и значению), период (в том числе «Вчера» и «С моей последней синхронизации»), автор, действие, тип объекта, история конкретных элементов. Включённые фильтры видны строкой под поиском, каждый снимается крестиком.
- **Действия:**
  - двойной щелчок по строке показывает элемент в модели или открывает вид;
  - «Выделить все из списка в модели» (меню «⋯») выделяет всё, что попало в отфильтрованный список (например, всё, что Иванов изменил сегодня); больше 20 000 элементов Revit выделяет очень медленно — об этом плагин предупредит;
  - «Экспорт CSV» сохраняет для Excel весь отфильтрованный список, а не только показанные в таблице строки.
- **События модели** (своя вкладка): кто и когда открыл, синхронизировал, обновил, сохранил и закрыл модель.
- **3D-вид изменений.** Кнопка «3D» в панели строит свой 3D-вид, где изменения за выбранный период раскрашены, а остальная модель бледная. Подробнее — в разделе «3D-вид изменений».
- **Актуализация журнала.** Пункт меню «⋯» сверяет журнал с текущей моделью и убирает у всей команды записи об изменениях, которых в модели нет. Убранное можно вернуть.

## Установка и обновление

Модуль входит в плагин RAS v. 2.0: ставится один раз вместе с плагином и обновляется сам при запуске Revit — см. `README.md` в корне проекта («Установка», «Обновление»). Работает в Revit 2026; в Revit 2023 «О плагине» показывает «не работает в Revit 2023». На ленте — кнопки «Журнал изменений», «История выделенного» и «Настройки» (на какой панели и в каком отделе — раскладка плагина).

Прежний отдельный плагин RAS-Model History (раньше — SpyPlugin) установка плагина убирает сама, а личные папки прежних версий (вид панели, настройки, кэш, неотправленные записи) модуль переносит при первом запуске.

### Где хранится журнал

- Общая папка журналов — папка данных модуля на сервере RAS v. 2.0: `\\10.10.1.77\Shared\BIM\00_Плагины\00_RAS\RAS_v_2.0\Data\RAS-Model History`. Каждый пишет туда сразу после установки, настраивать ничего не нужно, в настройках этой папки нет. Прежняя папка журналов отдельного плагина (`\\10.10.1.77\Shared\BIM\Полетаев Кирилл\RAS-Model History`) больше не используется.
  - **Права:** все пользователи могут создавать в ней папки и файлы и дописывать их.
  - **Рекомендация:** запретите удаление и изменение чужих файлов. Каждый пишет только в свои файлы `<пользователь>@<компьютер>_<месяц>.jsonl`.
  - Если папка недоступна (нет сети или прав), записи копятся на компьютере пользователя в `%LocalAppData%\RAS_v_2.0\RAS-Model History\Spool` и отправляются сами, когда папка снова доступна.

### Если модели хранятся на Revit Server

- Журнал в сам Revit Server не пишется: для него нужна обычная сетевая папка Windows. Подойдёт папка на файловом сервере или общий ресурс на машине с Revit Server.
- У каждой модели в этой папке своя подпапка. Для Revit Server её определяет **GUID модели-хранилища**, который Revit Server присваивает каждой модели. Поэтому:
  - одна и та же модель, открытая через разные Host-серверы (в разных офисах) или по имени сервера и по IP, пишет в одну подпапку;
  - разные модели с одинаковым именем и даже одинаковым путём на разных серверах не смешиваются.
- Прежние версии плагина определяли подпапку модели на Revit Server по полному пути вместе с именем сервера. Такая старая подпапка тоже читается, и история не теряется; новые записи пишутся в новую. Старая подпапка находится по пути, под которым модель открыта у вас: если кто-то открывал её через другой сервер, его старые записи остаются в отдельной подпапке.
- Если офисов несколько, общая папка должна быть доступна из всех офисов. Иначе у каждого офиса будет своя половина истории.

### Настройки: где лежат и как поменять

Кнопка «Настройки» (и пункт «Настройки…» в меню «⋯» журнала) — только у BIM-специалистов; у остальных она серая.

**Тема** — личная: «Оформление» в окне, действует сразу и только у вас.

**Всё остальное — для всей команды:** что отслеживать, лимиты, папка журналов, период, с которого открывается журнал.
- Поменяли в окне → «Сохранить»: настройки записываются в общий файл на сервере (`Data\RAS-Model History\settings.json` в папке плагина). У вас действуют сразу, у коллег — после перезапуска Revit. В окне видно, кто и когда сохранил их последним.
- **Папка журналов.** Пусто — папка по умолчанию (`Data\RAS-Model History`). Другая папка начинает действовать у каждого с перезапуска Revit; до этого коллеги пишут в прежнюю. Журналы из прежней папки сами не переносятся — перенесите их папки вручную (лучше вечером, когда никто не работает), иначе прежняя история не будет видна. Перед сохранением окно проверит, что в новую папку можно писать, и предупредит.
- Сервер не отвечает — плагин работает по последним известным настройкам (их копия — на компьютере), а сохранить в окне не получится.
- Общий файл ещё ни разу не сохраняли — действуют исходные настройки из плагина.

**Если что-то не работает:** в Revit — «О плагине» → «Показать журнал ошибок». Откроется папка с файлом журнала ошибок `ras.log` (`%LocalAppData%\RAS_v_2.0\Logs`) — отправьте этот файл разработчику и коротко напишите, что делали и в какой модели.

## Как пользоваться

1. Откройте модель и нажмите **Журнал изменений**.
   Журнал открывается в отдельном окне (см. «Окно или панель» ниже); его можно закрепить в панели Revit.
2. Работайте как обычно: записи появляются в течение 1–2 секунд. Записи коллег подтягиваются автоматически, пока панель открыта: обычно в течение 5–15 секунд (панель проверяет папку каждые 5 секунд, а Windows обновляет список файлов сетевой папки с задержкой до 10 секунд).
3. Выделите элемент в модели. В подробностях появится блок «Выделено в Revit»: создатель, кто последним синхронизировал, кто занял сейчас и ссылка «История в журнале». Если записей нет, карточка пишет, за какой период: элемент могли менять раньше — увеличьте период. Значок «глаз» в строке фильтров включает **«Следить за выделением»**: список сам показывает историю того, что выделено в Revit.
4. **История выделенного** на ленте показывает в журнале только записи о выделенных элементах. Если ничего не выделено — историю открытого вида: сам вид и нарисованное на нём (размеры, марки, аннотации).
5. Выберите строку. В подробностях появятся имя элемента, кнопки «Показать в модели», «История элемента», «Копировать ID» и четыре вкладки:
   - **«Запись»** — автор и компьютер, время, источник, команда Revit, уровень, рабочий набор, статус с пояснением;
   - **«Было → стало»** — какие параметры изменились в этой записи. Если параметров нет, объясняется почему: Revit только пересчитал элемент (соединения, помещения, правка соседних) или «было» неизвестно (подготовка модели ещё шла);
   - **«Все параметры»** — полный список параметров с поиском по имени и значению. Для удалённого элемента это значения на момент удаления, для остальных — текущие значения по последнему снимку;
   - **«История»** — все записи об этом элементе за выбранный период. Щелчок по записи показывает её в списке.
6. Правый щелчок по ячейке — **«Равно» / «Не равно»** по её значению: например, «Равно: Категория «Стены»» или «Не равно: Автор «Иванов»». Это условие окна «Фильтр»: оно появляется среди включённых, снимается крестиком и правится в окне.
7. **Фильтр** — кнопка рядом с сортировкой, как фильтры Revit. Строки условий «поле — условие — значение»: «равно», «не равно», «больше», «больше или равно», «меньше», «меньше или равно», «содержит», «не содержит», «начинается с», «не начинается с», «заканчивается на», «не заканчивается на», «имеет значение», «не имеет значения». Условия соединяются «И» (все выполняются) или «ИЛИ» (хотя бы одно). Внизу окна видно, сколько записей подходит.
   - **Поля:** запись (действие, автор, компьютер, команда Revit, статус, источник), элемент (категория, тип объекта, имя, тип / семейство, ID, уровень, рабочий набор, вид, создатель, кто последним синхронизировал), изменения («Изменён параметр», «Было» и «Стало» выбранного параметра) и любой параметр элемента.
   - **Значение** выбирается из списка (там то, что есть в списке записей, и сколько раз) или вводится. Числа сравниваются как числа: «больше 3000» подходит и к «3500 мм». Текст — без учёта регистра.
   - **«Изменён параметр»**: «равно Длина» — записи, где «Длина» менялась, «не равно Длина» — где не менялась.
   - **Параметр элемента**: у созданных и удалённых значение берётся из журнала (на момент создания или удаления), у изменённых — текущее из модели: журнал хранит только изменившиеся параметры. Из модели — не больше чем для 20 000 записей, сверх этого учитываются только значения из журнала.
   - Незаполненное условие не действует. Фильтр работает на вкладке «Изменения» и не влияет на 3D-вид.

### Как устроена панель

Сверху вниз:

1. **Верхняя строка.** Название модели (в подсказке — режим работы и папка журнала), вкладки **«Изменения»** и **«События модели»**. Справа значки «3D» (3D-вид изменений), «Обновить», «Экспорт CSV» и меню «⋯»: «Актуализировать журнал…», «Выделить все из списка в модели», «Открыть папку журнала», «Настройки…». Если нет связи с общей папкой журналов, под названием модели держится предупреждение: изменения коллег не обновляются, ваши копятся на компьютере и уйдут, когда связь появится.
2. **Фильтры.** Поиск, «Период», «Автор»; на вкладке «Изменения» ещё «Действие», «Ещё», «Фильтр» (на кнопке — число условий), кнопка сортировки и «Следить за выделением».
   - «Период»: «Сегодня», «Вчера», 3, 7, 30, 90 дней, «Год», «Всё время» и «С моей последней синхронизации». Для последнего время синхронизации видно в строке состояния, а то, что пришло при самой синхронизации, не показывается: это не новые изменения.
   - В «Действие» флажками выбирается, что показывать: создание, изменение, удаление.
   - «Ещё» открывает строку с редкими настройками: тип объекта, «Без дублей», «Скрыть не попавшие в хранилище» (в одиночном файле — «Скрыть закрытые без сохранения»), «Скрыть отменённые (Ctrl+Z)», «Показать убранные», «Служебные элементы» (виден, только если такие записи есть в журнале). Число в скобках («Ещё (2)») — сколько из них изменено.
   - «Без дублей», «Скрыть не попавшие в хранилище» и «Скрыть отменённые» включены по умолчанию: это то, чего фактически не было. «Скрыть отменённые» прячет пары «правка + её отмена (Ctrl+Z)» — правку и отмену одной команды в одном сеансе; повтор (Ctrl+Y) остаётся виден. Значок над таблицей появляется, когда такой флажок выключили.
   - Под строкой фильтров видны включённые фильтры. Крестик снимает один, «Сбросить все» — все сразу (период и столбцы параметров остаются). Условия «ИЛИ» показываются одним значком.
3. **Список.** По умолчанию шесть столбцов: время в виде «ДД.ММ.ГГГГ ЧЧ:ММ» (секунды — в подсказке), действие, автор, объект (имя, а под ним категория и ID), что изменилось, статус — значок и текст рядом: «✓ в хранилище», «не синхронизировано», «✗ не попало в хранилище» (пояснение — в подсказке).
   - **Остальные столбцы** — правым щелчком по заголовку таблицы: тип объекта, категория, тип, ID, команда Revit, уровень, рабочий набор, вид, источник, создатель, компьютер. Там же «Вернуть столбцы по умолчанию». Ширина, порядок и набор столбцов запоминаются.
   - **Операции.** Если одна операция Revit затронула несколько элементов (перемещение, копирование, изменение типа), она показывается одной строкой «Перемещение · 12 элементов» с разбивкой по категориям. Строка раскрывается значком ▸, двойным щелчком или клавишей →, сворачивается клавишей ←. «Показать в модели» у операции выделяет все её элементы. Операция сортируется как одно целое, записи внутри — по тем же правилам. Выключить: «Сортировка» → «Записи одной операции Revit — одной строкой».
   - **Сортировка и группировка — как в спецификации Revit.** Кнопка со значком сортировки в строке фильтров (на ней написан текущий порядок, например «автор ↑, время ↓») открывает окно «Сортировка и группировка»: «Сортировать по» и до трёх «Затем по», у каждого уровня — «По возрастанию» / «По убыванию» и флажок **«Заголовок»**. С заголовком над каждой группой одинаковых значений появляется строка «Автор: Иванов (124)»; группу можно свернуть стрелкой, вложенные заголовки сдвинуты вправо. «Сбросить» возвращает порядок по умолчанию: по времени, новые сверху. Можно сортировать и по «Столбцу параметра».
   - **Щелчок по заголовку столбца** делает этот столбец первым уровнем сортировки, повторный щелчок меняет направление. Уровни с заголовками при этом остаются первыми. Стрелки в заголовках показывают все уровни.
   - **События модели** — на своей вкладке: кто и когда открыл, синхронизировал, сохранил и закрыл модель, когда журнал актуализировали.
4. **Подробности.** Если панель широкая (пристыкована снизу), они стоят справа от списка, если узкая (сбоку) — под списком. Раскладка меняется сама, размер меняется перетаскиванием разделителя и запоминается.
5. **Строка состояния.** В левом нижнем углу — **«Модель запомнена: N %»** с полоской: сколько модели плагин уже запомнил (элементы и их параметры). Работать можно сразу; пока меньше 100 %, у ещё не запомненных элементов может не быть «было» (выделенное запоминается сразу). Когда готово — «✓ Модель запомнена». Дальше — сколько записей и сколько из них созданий, изменений и удалений (изменения со статусом «✗» — которых фактически не было — в итоги не входят); последнее сообщение.

**Тема.** Панель и окна плагина бывают светлыми и тёмными. По умолчанию тема следует за темой интерфейса Revit (Revit 2024 и новее) и меняется сразу вместе с ней. Выбрать светлую или тёмную тему вручную можно в «Настройки» → «Оформление».

**Окно настроек** (только у BIM-специалистов). «Оформление» — личное, остальное — для всей команды (см. «Настройки: где лежат и как поменять» выше). Внизу окна — что делать, если что-то не работает. Окно растягивается мышью за край или уголок; если всё не помещается по высоте, появляется прокрутка. Кнопки «Сохранить» и «Отмена» всегда внизу.

**Окно или панель.** «Журнал изменений» открывает журнал в обычном окне: его можно растянуть, развернуть на весь экран или перенести на другой монитор; окно открывается там же, где его закрыли. Кто привык к панели внутри Revit, нажимает в окне кнопку со стрелками «Закрепить в панели Revit» — дальше журнал открывается в панели, а та же кнопка в панели возвращает его в окно.

Вид панели (столбцы, сортировка и заголовки, свёрнутые группы, размер подробностей, открытая вкладка, «Записи одной операции — одной строкой», «Следить за выделением») хранится в `%AppData%\RAS_v_2.0\RAS-Model History\ui.json`. Если удалить этот файл, панель вернётся к виду по умолчанию. Файл от прошлой версии плагина подхватывается: старые столбцы «Статус» (значок и текст) объединяются в один.

### 3D-вид изменений

Кнопка **«3D»** в верхней строке панели открывает окно «Показать изменения в 3D». Окно заполнено периодом, автором и действиями из панели. Поиск, «Фильтр», тип объекта и история выбранных элементов на 3D-вид не влияют.

- **Период:** те же, что в панели (в «С моей последней синхронизации» рядом показано её время), и «Свой период» — даты «с» и «по» в виде ДД.ММ.ГГГГ.
- **Чьи изменения:** все авторы или выбранные; список — за всё время журнала.
- **Что показать:** созданные, изменённые, изменённые без отличий в параметрах.
- **Цвета:** по действию (по умолчанию созданное — ярко-зелёным, изменённое — ярко-оранжевым, без отличий — синим; каждый цвет можно выбрать из 12) или по автору (у каждого свой цвет). Остальная модель — заметнее (прозрачность 40 %), обычно (65 %), бледнее (85 %) или скрыта (видны только изменения); она серая, с тонкими серыми кромками, чтобы формы читались и без теней. Заливка — «ярко, без теней» (стиль «Согласованные цвета», по умолчанию) или «объёмно, с тенями». Изменённые элементы обведены толстой линией того же цвета, темнее; если в Revit включены «Тонкие линии», обводка будет тонкой. Если внутри изменённого элемента есть другое изменение (новая арматура в балке), элемент становится полупрозрачным, чтобы было видно то, что внутри; в легенде сказано, сколько таких. Выбор запоминается; «Цвета по умолчанию» возвращает исходные.
- **Подрезка:** рамка вокруг изменений, этажи с уровня по уровень или без подрезки. Можно скрыть перекрытия, крыши и потолки — изменённые среди них остаются видны.

Плагин строит свой вид «RAS-Model History — изменения (имя пользователя)»: остальная модель на нём серая и прозрачная, изменения раскрашены яркими цветами и обведены. Рабочие виды не меняются, а свои действия с этим видом плагин в журнал не пишет. Над списком появляется легенда: цвета, сколько показано и чего на виде нет. **Закройте вкладку вида — он удалится сам.** Если Revit закрыли с открытым видом, он удалится при следующем открытии модели. Закройте вкладку вида до синхронизации: иначе вид уйдёт в хранилище и коллеги увидят его в диспетчере проекта (в их журналы он не попадёт).

Цвет — по итогу за период: каким элемент был в начале периода и каким стал.

| Что было с элементом за период | На виде |
|---|---|
| Создан (и потом сколько угодно правился) | цвет «созданное» |
| Существовал раньше, параметры отличаются от начала периода | цвет «изменённое» |
| «Было» неизвестно (снимок ещё не был готов) | цвет «изменённое» |
| Revit отметил «изменён», но параметры те же: изменили и вернули, Revit только пересчитал соединения или помещения | не показан (флажком — цветом «без отличий») |
| Создан и удалён за период | не показан |
| Удалён | на виде нет, число — в легенде |

Не учитываются: изменения, не попавшие в хранилище; записи, убранные при актуализации; дубли — то же изменение, полученное коллегой при синхронизации (со временем получения). «С моей последней синхронизации» не учитывает то, что пришло при самой синхронизации. Отмена удаления (Ctrl+Z) не считается созданием. Элемент ищется по постоянному UniqueId: номер нового элемента Revit может сменить при синхронизации. В записях старых версий плагина нельзя отличить «параметры не поменялись» от «было неизвестно» — такие изменения без параметров считаются «без отличий».

Параметр «Редактирует» (кто занял элемент) больше не записывается: он менялся, когда элемент просто брали для правки, и выглядел как изменение.

### Значение любого параметра, в том числе у удалённых элементов

Правый щелчок по заголовку таблицы → **«Добавить столбец параметра…»**: откроется список всех параметров, найденных у элементов модели, с поиском. После выбора в таблице появится столбец с этим параметром. Таких столбцов можно добавить несколько; набор запоминается. Убрать столбец — снять флажок с него в том же меню (там же — флажки остальных столбцов).

| Запись | Что показано в столбце |
|---|---|
| Удалён | значение на момент удаления |
| Изменён, и этот параметр менялся | «было → стало» |
| Остальные | текущее значение (по последнему снимку) |

По столбцу параметра можно сортировать — щелчком по его заголовку или в окне «Сортировка» (в том числе с заголовками групп); все столбцы параметров выгружаются в CSV. Поиск тоже ищет по значениям параметров удалённых элементов: например, можно найти удалённую дверь по марке.

Колонка **«Источник»** показывает, откуда взялась запись:

| Источник | Что значит |
|---|---|
| В сеансе | Записано в момент изменения у самого автора. Самая точная запись: известны автор, время и команда. |
| Синхронизация | Изменение другого пользователя, полученное при синхронизации. Автор — последний, кто синхронизировал этот элемент. Время — момент получения. |
| Обновление | То же при «Обновить до последней версии». |
| С прошлого сеанса | При открытии модели: что изменили другие с вашего прошлого сеанса. |

Флажок **«Без дублей»** (в «Ещё», включён по умолчанию) скрывает записи «Синхронизация», если то же изменение уже записал сам автор (у него стоит плагин), в том числе раньше начала выбранного периода: вчерашняя правка, полученная коллегой утром, не попадает в «Сегодня». Удаление, полученное при синхронизации, пишется без автора и скрывается, если удаливший записал его сам.

### Статус: попало ли изменение в хранилище

Изменение попадает в журнал сразу, ещё до синхронизации. Поэтому у каждой записи есть столбец **«Статус»**:

| Статус | Что значит |
|---|---|
| ✓ в хранилище | После изменения автор синхронизировался (для одиночного файла — сохранил его). |
| … не синхронизировано | Автор ещё работает и не синхронизировался. |
| … только в локальной копии | Модель закрыта без синхронизации, но изменение сохранено в локальной копии. Оно попадёт в хранилище, если автор синхронизируется из этой же копии. |
| ✗ не попало в хранилище | Модель закрыта без синхронизации и без сохранения. Или автор открыл модель через новую локальную копию, а старая с несинхронизированными изменениями заменилась. Фактически изменения не было. |

В модели без совместной работы хранилища нет, и статусы называются «✓ сохранено», «… не сохранено» и «✗ закрыто без сохранения».

Строки со статусом «✗» показаны бледным курсивом. Флажок **«Скрыть не попавшие в хранилище»** в «Ещё» убирает их из списка. В подробностях записи статус объясняется словами, а при закрытии модели в журнал пишется событие, например «Закрытие без синхронизации: изменений не попало в хранилище — 3».

Как плагин это определяет. Все записи одного открытия модели помечаются номером сеанса. Синхронизации, сохранения локальной копии и закрытие тоже пишутся в журнал. При следующем открытии той же локальной копии плагин сверяет её версию: если это тот же файл, несохранённые в хранилище изменения прошлого сеанса «переезжают» в новый сеанс и получат «✓» после синхронизации. Записи, сделанные старыми версиями плагина, статуса не имеют.

### Актуализация журнала

Пункт **«Актуализировать журнал…»** в меню «⋯» панели сверяет журнал с тем, что сейчас в открытой модели. Кнопки на ленте нет: действие скрывает записи у всей команды — это инструмент BIM-менеджера. Она находит записи, которые модели противоречат:

| Запись | Противоречие |
|---|---|
| Удалён | элемент есть в модели |
| Создан | элемента в модели нет (или под этим ID теперь другой элемент) |
| Изменён | элемента нет, или у параметров остались значения «было» и ни одно не равно «стало» |

**Что убирается.** Только записи, которые не подтверждены хранилищем:

- **«✗ не попало в хранилище»** — изменение не синхронизировано и модель закрыта без сохранения, или локальная копия с изменением заменена новой. Такие записи убираются **все, без сверки с моделью**: по событиям сеанса уже известно, что изменения пропали, а сверка не всегда может это доказать (правка без параметров, «изменил и вернул»). Причина в списке — «не попало в хранилище: …»;
- записи старых версий плагина, у которых нет сведений о синхронизации. Только они сверяются с моделью (таблица выше), и осторожнее, при двух условиях:
  - после такой записи её автор уже синхронизировался или закрыл модель;
  - ваша модель после этого получила всё из хранилища: вы синхронизировались или нажали «Обновить до последней версии» в этом сеансе (для модели без совместной работы это условие не нужно).

  Иначе расхождение может значить лишь, что ваша копия устарела. В списке такие записи помечены «старая запись без сведений о синхронизации».

**Что не трогается никогда:**

- синхронизированные изменения («✓ в хранилище»). Если модель с тех пор изменилась, это история, а не ошибка;
- изменения, полученные при синхронизации от коллег;
- изменения коллег, которые ещё работают и не синхронизировались.

**Как сверяются старые записи одного элемента.**

- Записи идут от новой к старой. Пока запись противоречит модели, она уходит в список. На первой согласованной записи проверка элемента останавливается.
- Элемент ищется по UniqueId, а если его нет — по ID.
- Если в модели закрыт хотя бы один рабочий набор, отсутствие элемента не считается доказательством: он может быть в закрытом наборе.
- Изменённое значение, не совпадающее ни с «было», ни с «стало», тоже не повод убирать запись.
- Элементы, которые меняются, пока идёт проверка или открыт список, не трогаются: их записи могли не успеть попасть в журнал. К записям «✗» это не относится — они от модели не зависят.

**Как это выглядит:**

1. Плагин читает всю историю модели (не только выбранный период) и сверяет её с моделью в фоне. Ход проверки показан полосой над списком, кнопка «Остановить» прерывает проверку. Журналом в это время можно пользоваться как обычно.
2. Если несоответствия найдены, панель переходит в режим актуализации: фильтры скрываются, в списке остаются только найденные записи, в столбце «Причина» — чем запись не соответствует модели («⚠ удаление не попало в модель: элемент существует»).
3. **«Убрать из журнала (N)»** скрывает их у всех пользователей, **«Отмена»** ничего не меняет. После любой из кнопок панель возвращается к журналу.

Файлы журнала при этом не правятся: в журнал добавляется событие «Актуализация журнала: убрано записей … — N» с автором и временем. Панели всех пользователей по нему скрывают эти записи. Посмотреть убранные можно флажком **«Показать убранные»** в «Ещё»: они отмечены «⊘ убрано при актуализации». **Вернуть** запись: правый щелчок по ней → «Вернуть в журнал (у всех пользователей)». В журнал добавляется событие «возвращено в журнал», и запись возвращается у всей команды. Старые версии плагина этого события не понимают — у них запись остаётся убранной.

## Что важно знать

- **Полный снимок модели.** Revit не сообщает старые значения параметров, поэтому плагин в фоне запоминает параметры **всех** элементов. Порядок такой:
  1. элементы открытого вида (и каждого вида, который вы открываете);
  2. виды, шаблоны, типы, уровни, оси, фильтры, материалы;
  3. всё остальное.
  - Снимки хранятся на диске (`%LocalAppData%\RAS_v_2.0\RAS-Model History\Cache\<модель>`), а не в памяти. Для крупной модели это до нескольких сотен МБ.
  - **Повторное открытие — за секунды.** При закрытии модели снимки сохраняются. При следующем открытии той же модели, в том числе новой локальной копии того же хранилища, плагин сверяет версию каждого элемента (`Element.VersionGuid`). Совпала — снимок берётся с диска, изменился (например, его правил коллега) — элемент переснимается в первую очередь. Обычно это секунда-другая даже на большой модели.
  - Если закрыть модель без сохранения, снимки несохранённых правок отбрасываются: они не совпадают с файлом.
  - Значения параметров хранятся в том виде, в каком их показывает Revit («3000», «3,000 м»). Если поменять единицы проекта или язык Revit, снимки переснимаются, иначе изменение формата выглядело бы как изменение значений.
  - Пока вы работаете мышью и клавиатурой, снимок идёт короткими порциями, чтобы Revit не тормозил. Если не трогать их хотя бы 1,5 секунды — более крупными, примерно втрое быстрее.
  - Кэши моделей, которые не открывались больше 30 дней, удаляются автоматически. Срок и само сохранение между сеансами задаются в общих настройках команды.
  - После каждого изменения снимок элемента обновляется, так что «было → стало» известно для любой правки, в том числе через спецификацию, «Найти и заменить», Dynamo и другие плагины.
  - Удалённый элемент попадает в журнал со всеми своими параметрами, и эти значения видит вся команда. Если одной операцией удалено больше 1000 элементов, параметры в общий журнал пишутся для первых 1000, чтобы журнал не разрастался. У того, кто удалял, значения остальных всё равно видны до закрытия модели.
  - Самое долгое — **первое** открытие модели на компьютере. Пока идёт подготовка (прогресс внизу панели), у ещё не запомненных элементов может не быть «было». Элементы на открытом виде и выделенные запоминаются почти сразу. Полный снимок можно отключить в общих настройках команды. Тогда параметры экземпляров запоминаются только при выделении и после изменений.
- **Массовые операции.** Если одна операция затронула больше 5000 элементов, лишнее записывается одной сводной строкой с разбивкой по категориям. Параметры разбираются не больше чем для 500 элементов на операцию. Оба лимита задаются в общих настройках команды.
- **Изменения коллег без плагина:**
  - автор определяется, только если модель с совместной работой;
  - время у таких записей — момент синхронизации, а не момент правки;
  - удаления видны без автора.

  Чтобы журнал был полным, поставьте плагин всем.
- **«Видимость/Графика».** Для видов и шаблонов отслеживаются фильтры и скрытые категории. Переопределения цвета и линий фиксируются как «Изменён» без детализации.
- **Служебные элементы.** Внутренние объекты Revit без категории, линии эскизов и временные размеры по умолчанию не записываются. Их запись включается в общих настройках команды.
- **Производительность.** После открытия модели плагин в фоне готовит данные: сначала сведения об элементах, затем их параметры. Прогресс показан внизу панели. Работа идёт порциями, пока Revit простаивает, и не мешает работать. Revit API однопоточный, поэтому распараллелить снимок нельзя. При первом открытии большой модели он занимает несколько минут, при повторных — секунды. Сколько снимков взято из кэша и сколько переснято, видно в журнале ошибок плагина `%LocalAppData%\RAS_v_2.0\Logs\ras.log` (строка «Snapshot cache: …»).
- **Хранение журнала.** Журнал хранится вне модели: файл `.rvt` не растёт. Если сетевая папка недоступна, записи копятся в `%LocalAppData%\RAS_v_2.0\RAS-Model History\Spool` и отправляются автоматически, когда папка снова доступна; пока связи нет, в панели держится предупреждение.
- **Модели с одинаковыми именами** не смешиваются. Подпапка журнала и кэш снимков определяются полным путём к файлу (для Revit Server — GUID модели-хранилища), а имя в названии подпапки нужно только для удобства. Смешение возможно в одном случае: старый файл удалили, а на его место по тому же пути положили другую модель. Тогда новая модель продолжит историю старой. Чтобы этого избежать, переименуйте или перенесите в архив старую подпапку журнала. Кэш снимков в этом случае не пострадает: версии элементов не совпадут, и всё переснимется.
- **Ошибки плагина** пишутся в `%LocalAppData%\RAS_v_2.0\Logs\ras.log` (окно «О плагине» открывает этот файл).
- **Личные папки прежних версий** (`%AppData%` и `%LocalAppData%`: `RAS-Model History`, ещё раньше `SpyPlugin`) при первом запуске переносятся в `…\RAS_v_2.0\RAS-Model History`. Что уже есть в новой папке, не перезаписывается; неотправленные записи переносятся все и досылаются.

## Формат журнала

```
<Папка журналов>\<ИмяМодели>_<хэш пути к хранилищу>\
    model.json                              — название и путь модели
    ivanov@PC-012_2026-09.jsonl             — записи пользователя за месяц, одна строка = одна запись JSON
```

Основные поля записи:

| Поле | Значение |
|---|---|
| `t` | время |
| `u` | автор |
| `pc` | компьютер |
| `wa` | учётная запись Windows того, кто записал («ДОМЕН\логин»); в записях прежних версий нет |
| `fn` | полное имя этой учётной записи из каталога компании; нет — не удалось узнать |
| `k` | действие: `Created` / `Modified` / `Deleted` / `Event` (если поля нет — `Created`) |
| `s` | источник: `Live` / `Sync` / `Reload` / `Open` |
| `op` | операция: `Undo` / `Redo` / `Rollback` |
| `tx` | команда Revit |
| `id`, `uid` | ElementId и UniqueId |
| `cat` | категория |
| `ot` | тип объекта |
| `n` | имя |
| `tp` | семейство : тип |
| `lv` | уровень |
| `ws` | рабочий набор |
| `vw` | вид-владелец |
| `cr` | создатель |
| `lc` | последний синхронизировавший |
| `p` | изменённые параметры: `[{"n": имя, "o": было, "v": стало}]` |
| `bk` | у «Изменён»: `true` — «было» известно (пустой `p` = параметры не поменялись), `false` — «было» неизвестно; нет поля — запись старой версии |
| `st` | все параметры элемента: у удалённого — на момент удаления, у созданного — сразу после создания: `[{"n": имя, "v": значение}]` |
| `ss` | сеанс (одно открытие модели) |
| `et` | тип события модели: `Open` / `Close` / `Commit` / `SaveLocal` / `Resume` / `Lost` / `Reload` / `Exclude` / `Restore` / `FromDetached` (модель сохранена из отсоединённой копии) |
| `pid`, `pr`, `pn` | у «Удалён»: удалён вместе с элементом `pid` — номер записи его удаления `pr` и его название `pn` («Стены · Базовая стена»); нет полей — удалён сам |
| `ex` | у события `Exclude` — id записей (`r`), убранных при актуализации; у `Restore` — возвращённых в журнал |

Файлы можно разбирать скриптами, загружать в Power BI или Excel (Power Query → JSON).
