# RAS-Model History — решения и идеи

Что решили по модулю, почему так и что отвергли. Здесь же идеи и планы на будущее. Перед развитием модуля прочитать этот файл: многое уже обдумано, и причины записаны.
Как модуль устроен сейчас — `MODULE.md`, общие правила — `PRINCIPLES.md` в корне.

Как вести файл:
- Новое решение — сверху своего раздела: дата, решение, почему, что отвергли, состояние (сделано — с коммитом; запланировано; отложено).
- Решения не удаляются. Передумали — новая запись со ссылкой на прежнюю, у прежней в состоянии — «заменено».
- Идея без решения — в раздел «Идеи».

## Запланировано

Порядок — сверху вниз. Шаг 6 переезда (Revit 2023) отложен решением разработчика (06.10.2026).

### Связь журналов (06.10.2026)

**Решение.** Модель по-прежнему узнаётся по номеру хранилища Revit Server (`ModelIdentity.Key`). Если история модели разделилась, журналы связываются:
- Автоматически: при открытии модуль ищет в общей папке журнал с тем же путём на Revit Server (без имени сервера; путь — в `model.json`) и другим номером. Нашёл — полоса в панели «Найдена прежняя история… [Связать] [Это другая модель]», без всплывающих окон.
- Вручную: меню «⋯» → «Связанные журналы…» — список журналов общей папки (модель, путь, записей, период, авторы), связать / отвязать. С предупреждением «Только для BIM-менеджера».
- Связь хранится на сервере, в папке журнала модели (`links.json`), и общая для всех. Связывание и отвязка пишутся событием в журнал, ничего не удаляется. Панель, 3D-вид и аналитика читают связанные журналы вместе, дубли отсекаются по номеру записи. Логика — без Revit, с тестами.

**Почему.** Хранилища — на Revit Server. Когда удалённое восстанавливают, локальную копию сохраняют вместо хранилища под тем же именем и по тому же пути. У нового хранилища, скорее всего, другой номер (проверить на тестовой модели), и журнал модели начинается в новой папке — прежняя история пропадает из панели.

**Отвергли.**
- Узнавать модель по пути и имени вместо номера. Восстановленная модель тогда сама продолжала бы историю, но ключи всех моделей пришлось бы переносить, а переименование или перенос модели начинали бы историю заново. Связь журналов решает обе задачи без смены ключа.
- Ограничить связывание правами. Кто связывает журналы — договорённость в компании; технически — только предупреждение.

**Состояние:** запланировано.

### «Хранилище заменено копией» (06.10.2026)

**Решение.** Модуль замечает замену хранилища: последней версии хранилища, которую он помнит, нет в истории модели (`Document.IsValidVersionGUID`), или номер хранилища сменился при том же пути. Тогда — событие в журнал «Хранилище заменено копией: кто, когда». Записи, синхронизированные после момента копии, помечаются «✗ потеряно при восстановлении» (момент копии — по номеру версии хранилища, который модуль пишет при синхронизациях). «Актуализация» должна работать и в этом случае.

**Почему.** При замене хранилища копией пропадает чужая работа, сделанная после момента копии, а журнал продолжает считать её «✓ в хранилище». Сравнение «что изменилось с прошлого раза» при этом молча не срабатывает: Revit не сравнивает версии из разных историй хранилища.

**Отвергли (пока).** «Вернуть удалённое из копии» — возвращать из копии только удалённые элементы, а не заменять хранилище целиком (этап 1 — модуль выделяет удалённое в открытой копии по идентификаторам из журнала; этап 2 — переносит сам). Решает потерю чужой работы в корне, но пока не нужно. Ограничения, если вернёмся: вернувшийся элемент — копия с новым ID (марки и размеры на него — заново), арматуру возвращать вместе с основой.

**Состояние:** запланировано.

### Аналитика для главного конструктора (06.10.2026)

**Решение.** Главный конструктор открывает отчёт и видит жизнь модели за период: кто над какими конструкциями работал, сколько времени, сколько ушло на оформление. Плагин сам сводит записи в работы — «Иванов, 1–5 октября, СЖм-12: ~6 ч, 14 операций, 214 стержней», а не показывает сырые записи.

1. **Марка конструкции — в каждой записи** (текущее значение, не только когда её меняют). Параметр марки свой для каждой категории: таблица «категория → параметры (первый заполненный)» в общих настройках компании; для арматуры без марки — марка основы. Таблицу даст разработчик.
   *Почему:* сейчас марка есть только у созданных (не больше 500 элементов одной операции) и удалённых записей. Правка шага у стержня, созданного до плагина, иначе не относится ни к какой марке. В момент правки плагин и так читает все параметры элемента — брать марку почти бесплатно.
   *Уточнение:* работу считать по тем, кто создавал и правил элементы с маркой, а не по тому, кто её присвоил: марки массово переставляет и проверяющий.
2. **Присутствие.** Отрезки «активен; открытый вид; выделенное и его марка» — новая строка только при смене состояния. В отдельных файлах рядом с журналом: панель их не читает, журнал не засоряется. Объём — десятки строк в день на человека. Снятие — в простое Revit, доли миллисекунды. Сначала на 2–3 людях.
   *Почему:* Revit сообщает об изменении, когда операция закончена; между правками — тишина, и без присутствия её приходится угадывать по перерывам. Это поминутный учёт работы — сотрудников предупредить.
3. **Время работы.** Отрезки работы человека — правки с перерывами меньше порога (~15 мин), уточнённые присутствием. Время между правками — на марку следующей правки. Считаются операции (пакеты), а не элементы: «Копировать 200 стержней» — одно действие. Правки без марки — по группам: «Оформление» (аннотации, виды, листы, спецификации — группа записи `ot`), «Прочее». Это оценка, не табель — так и подписывать в отчёте.
4. **Отчёт** — один файл HTML с интерактивными дашбордами, как в Power BI: фильтры (период, люди, марки, категории), перекрёстный отбор, переход вглубь (марка → элементы → правки), лента «кто над чем по дням», тепловая карта «люди × дни», «горячие» марки. Данные и библиотека графиков вшиты в файл: открывается в браузере без сети, пересылается; в Revit библиотека не загружается.
5. **По расписанию.** Программа без Revit (логика модуля, подключённая исходниками, как в проверках) собирает отчёт каждый день планировщиком Windows на компьютере разработчика: `Reports\<модель>\<дата>.html` и всегда свежий последний. В планировщике — «запускать при первой возможности», иначе при выключенном компьютере отчёт не соберётся. Папка `Reports` — только руководителям: в ней поимённые данные о работе.

**Отвергли.**
- Power BI и подобные системы — отдельный инструмент и лицензии.
- Окно с графиками внутри Revit — сторонние библиотеки графиков в Revit 2023 конфликтуют с другими плагинами, рисовать вручную долго.
- Служба на сервере с дашбордом «в реальном времени» — отдельная программа и компьютер-сервер; можно вернуться позже, отчёт тот же.
- Отдельная сущность «ключ конструкции» — марка в параметре и есть ключ, нужно только писать её в каждую запись.

**Состояние:** запланировано. Ждёт: таблицу «категория → параметр марки».

## Принято и сделано

### Журнал открывается в отдельном окне (05.10.2026)

**Решение.** «Журнал изменений» открывает обычное окно, как «Настройки»: растягивается, разворачивается на весь экран, переносится на другой монитор, запоминает место. Закрепить журнал в панели Revit — кнопкой в окне, выбор запоминается у каждого (`UiState.OpenInWindow`, по умолчанию — окно).
**Почему.** У стыкуемой панели Revit нет «Развернуть» — это ограничение Revit API, не модуля. Окно держится поверх Revit, поэтому панель оставлена по желанию.
**Отвергли.** Только кнопка «в окно» при панели по умолчанию — неудобно: каждый раз лишнее действие.
**Состояние:** сделано (`ff8217f`, `c7e87ff`).

### «Сотрудник» — учётная запись Windows в записях (05.10.2026)

**Решение.** Каждая запись несёт учётную запись Windows (`wa`, «ДОМЕН\логин») и полное имя из каталога компании (`fn`) того, кто записал. В подробностях записи — строка «Сотрудник». Для записей из синхронизации сотрудник автора ищется по его собственным записям (`EmployeeIndex`).
**Почему.** «Автор» — имя пользователя Revit: его задаёт сам человек, оно бывает чужим, и по нему долго искать сотрудника. Учётную запись Windows не подменить без чужого пароля.
**Отвергли.**
- IP-адрес: раздаётся автоматически и меняется, при VPN — общий; имя компьютера айтишникам полезнее.
- Сотрудника в столбце «Автор» и предупреждение, когда под одним именем Revit работают разные учётные записи: учётная запись и так видна в подробностях.
**Ограничение.** У записей из синхронизации сотрудник определяется по имени Revit — там подмена возможна.
**Состояние:** сделано (`f813649`).

### Журналы — одна папка на сервере (05.10.2026)

**Решение.** Журналы пишутся и читаются только в `Data\RAS-Model History` на сервере RAS v. 2.0. Прежняя папка отдельного плагина не читается; на сервере она оставлена как есть.
**Почему.** В прежней папке была только проверочная история (события открытия и закрытия одной модели). Папка журналов задаётся ядром, не настройками: если её можно поменять в настройках, одного неверного файла хватит, чтобы история команды разделилась.
**Отвергли.** Читать обе папки до шага 7 — лишняя сложность при пустой прежней папке.
**Состояние:** сделано (`e646c64`, `9708cc7`).

## Идеи

- Сотрудник в столбце «Автор» вместо имени Revit (имя Revit — в подробностях).
- Предупреждение, когда под одним именем Revit работают разные учётные записи Windows.
- Отчёт: недельная сводка по понедельникам; служба на сервере с дашбордом в реальном времени.
- Журнал после перезапуска Revit открывается в окне сам, если его оставили открытым.
