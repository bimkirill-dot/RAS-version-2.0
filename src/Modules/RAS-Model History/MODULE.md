# RAS-Model History — модуль журнала изменений модели

Журнал изменений модели Revit 2026: кто, что и когда создал, изменил или удалил; фильтр, сортировка, 3D-вид изменений.
Общие правила плагина — `PRINCIPLES.md` в корне, сборка и выпуск — `CLAUDE.md` в корне. Описание для пользователей —
`README.md` рядом (написан для прежнего отдельного плагина; разделы об установке устарели до шага 7).

## Устройство

- `App.cs` — стыкуемая панель, кнопки и подписки на события Revit — через контекст ядра (`ModelHistoryModule` → `App.Start`).
- `Tracking/` — запись изменений (`ChangeTracker`, `Jobs`), снимки параметров («было → стало», `ParameterSnapshot`, `SnapshotStore`), статус синхронизации (`SyncStatus`), актуализация журнала (`JournalAudit`), «Без дублей» (`JournalDedup` — общий для панели и 3D-вида), 3D-вид изменений: итог за период `PeriodDiff` (без Revit и WPF — проверяется на журналах вне Revit) + построение вида `ChangesView3D`. Окно — `UI/ChangesViewWindow.xaml` + `ChangesViewDialog.cs`, вызов — `RevitActions.ShowChangesView`.
- `Storage/` — запись/чтение журнала в общей папке (`LogStore`, `LogReader`, jsonl), настройки (`SpySettings`), локальное состояние моделей (`LocalState` → `state.json`: последняя версия модели, время последней синхронизации с ключом `commit|…`), вид панели (`UiState` → `%AppData%\RAS-Model History\ui.json`). Общая папка журналов зашита в плагин (`Storage/SharedFolder.cs`, через `SpySettings.SharedLogFolder`), в настройках и интерфейсе её не выбирают; `LogFolder` из старых settings.json вырезается при разборе.
- `UI/` — панель `SpyPane.xaml(.cs)` + `MainViewModel.cs`, строки таблицы `ChangeRow.cs`, сортировка/группы `RowSorting.cs` + окно `SortWindow.xaml`/`SortViewModel.cs`, тема `ThemeResources.xaml` + `ThemeManager.cs`, группировка операций `OperationGrouping.cs`, фильтр `RecordFilter.cs` (условия, без WPF и Revit) + окно `FilterWindow.xaml`/`FilterViewModel.cs`, настройки `SettingsWindow.xaml`.

## Правила, о которые уже спотыкались

- **Название и прежние имена.** Модуль — «RAS-Model History», сборка `RASv2.ModelHistory.dll`, пространства имён `RASv2.ModelHistory.*`. Классы с приставкой `Spy` (`SpyPane`, `SpySettings`, кисти `Spy.*`) — от прежнего плагина SpyPlugin, их не переименовываем. Прежние имена обрабатываются: `LegacyFolders.Migrate` (первым в `App.Start`) переносит личные папки `SpyPlugin` → `RAS-Model History`; `build.cmd` (`Remove-LegacyInstalls`) удаляет прежние отдельные установки `RasModelHistory` и `SpyPlugin` из `Addins` — иначе журнал писали бы два плагина; 3D-виды «SpyPlugin — изменения (…)» и транзакции «SpyPlugin:» узнаются.
- **Revit API — только из контекста Revit**: события, `Idling` (`IdleWorkQueue` — порциями), действия из UI — через `ExternalEvent` (`RevitActions`). Из потока WPF и фоновых потоков Revit API не трогать.
- **Тема.** `ThemeResources.xaml` — ResourceDictionary с `x:Class`, подключается как `<local:ThemeResources />`. **Никаких `pack://`-адресов** (в Revit-плагине ненадёжны). Цвета — только через кисти `{DynamicResource Spy.*}` из `ThemeManager`, без жёстких цветов в разметке. Кисти заморожены, и при смене темы каждый словарь темы получает новые (вложенный `BrushDictionary` заменяется целиком). Менять цвет кисти на месте нельзя: WPF замораживает кисть, как только её через `DynamicResource` берёт стиль, применённый к элементу. Из-за этого падало «Сохранить» в настройках.
- **Локальный стиль поверх стиля темы — только со своим `x:Key`.** Неявный стиль с `BasedOn="{StaticResource {x:Type CheckBox}}"` в словаре окна получает пустой `BasedOn` (ссылка находит сам себя), и элементы рисуются системными. Так было с флажками окна настроек (стиль `Check`).
- **Фоновые задачи (`IdleWorkQueue`)**: `Step`, вернувший «не закончено», отдаёт простой — очередь в этом такте его больше не вызывает. Так задача может сама ограничить порцию (подготовка — 15 мс, пока человек работает).
- **Ключи кистей и стилей не должны совпадать** (был `Spy.Muted` и у кисти, и у стиля → панель не загружалась). Стили текста — с суффиксом: `Spy.MutedText` и т. п.
- **ui.json версионируется**: `UiState.CurrentVersion`. Если меняется набор/смысл столбцов — поднять версию и добавить миграцию в `SpyPane.ApplyColumnState` (`if (_state.Version < N)`).
- **Сортировка** — в модели представления, не в DataGrid: щелчок по заголовку перехватывается (`e.Handled = true`) → `MainViewModel.SortByColumn`. Логика уровней и групп — `RowSorting.cs` без WPF и Revit (держать её такой, чтобы можно было тестировать отдельно). Операция Revit (заголовок + записи) сортируется как одно целое.
- **Заголовки групп** — `ICollectionView` + `PropertyGroupDescription("Group1".."Group4")`, шаблон GroupItem с `Expander` (`Spy.GroupExpander`). `RowGroup` сравнивается по `Key`; свёрнутость хранится по ключу и переживает обновление списка. Группы — по сменам значения, как в спецификации Revit.
- Большие списки: виртуализация DataGrid (`IsVirtualizingWhenGrouping`, `ScrollUnit=Pixel`); сортировка по «Столбцу параметра» — не больше `MaxParamSortRows` (20 000) строк.
- Формат журнала (поля `t`, `u`, `k`, `p`, `st`…) описан в README — менять только с обратной совместимостью: журналы читают все версии плагина в команде.
- **Свои транзакции плагина** называются с `ChangesView3D.TransactionPrefix` («RAS-Model History:»; прежний «SpyPlugin:» тоже узнаётся) — `ChangeTracker.OnDocumentChanged` их в журнал не пишет. Любая новая правка модели плагином — только с этим префиксом. 3D-виды изменений, пришедшие при синхронизации (вид не закрыли до неё), `RemoteDiffJob` тоже пропускает.
- **Настройки: общие и личные.** Что отслеживать и лимиты — только из общего `RasModelHistory.settings.json` рядом с плагином (иначе в журнале команды дыры); в окне настроек эти разделы `IsEnabled=False`. Из личного `%AppData%\RAS-Model History\settings.json` читаются и туда пишутся только поля `SpySettings.PersonalSettings` (`UiTheme`, `DefaultPeriodDays`). Новое поле настроек — сначала решить, чьё оно; личное добавить в `PersonalSettings`.
- **«Без дублей»** смотрит и на записи до начала периода: `LogReader` копит ключи «живых» записей раньше `since` (`LiveBefore`), иначе вчерашняя правка, полученная коллегой утром, всплывает в «Сегодня». Удаление из синхронизации пишется без автора — скрывается по «живому» удалению того же id. Логика — в `JournalDedup`, панель и 3D-вид пользуются ею одинаково.
- **Актуализация** (`Exclude`) и возврат (`Restore`, пункт «Вернуть в журнал») — события модели с `ex`; `JournalAudit.ExcludedIds` применяет их по времени. Актуализация только в меню «⋯» панели, на ленте её нет намеренно: она скрывает записи у всей команды.
- **Периоды** в `MainViewModel`: число дней, `PeriodYesterday` (-1), `PeriodSinceMySync` (-2, время — `LocalState.GetLastCommit`; записанное при самой синхронизации — `ReceivedBy` — не показывается). 3D-вид пользуется тем же списком.
- **Положение в снимке**: `~loc`/`~rot` у элементов с `LocationPoint`/`LocationCurve`, у остальных элементов модели — габариты `~box` (целые мм). Без этого сдвиг арматуры или перекрытия был «изменён без отличий». Новый псевдо-параметр, которого нет в старых снимках, — либо не сравнивать при отсутствии в «было» (как `~box` в `DiffTo`), либо поднять `SnapshotStore.IndexFormat` (кэш готовится заново). Действия пользователя со своим 3D-видом изменений `Jobs.AddLive` не пишет.
- **Фильтр** (`RecordFilter`) — неизменяемый: каждое изменение — новый объект (фильтрация в фоне). Условия по «Параметру элемента» у изменённых читают снимки модели — только поток Revit: `Filter` возвращает `NeedsModelFilter`, условия доделывает `ApplyFilter` → `KeepByFilter` (не больше `MaxParamSortRows`). «Равно / Не равно» из меню ячейки — те же условия (`AddCellCondition`). Числа сравниваются как числа, только если после числа ничего нет или единицы через пробел («12_А500» — текст).
- **Флажки по умолчанию включены**: «Без дублей», «Скрыть не попавшие» (`HideVoid`), «Скрыть отменённые» (`HideUndone`, пары — `UndoPairs`). Значок над таблицей — когда флажок выключили; «Сбросить все» включает их обратно.
- **Актуализация**: записи «✗» (Discarded/LostLocal) убираются все без сверки с моделью (`JournalAudit.VoidFindings`), сверка (`BuildChecks`) — только для старых записей без статуса.
- **3D-вид**: изменённый элемент, в габаритах которого центр другого изменённого (арматура в балке), — полупрозрачный (`ChangesPalette.SeeThrough`), иначе заливка закрывает то, что внутри.
- **Итог за период** (`PeriodDiff`) группирует по `UniqueId` (id нового элемента меняется при синхронизации); отмена удаления (Undo) — не создание.
- **`bk` у «Изменён»**: `true` — «было» известно, `false` — неизвестно, нет — старая запись. Без этого пустой `p` не отличить от «было неизвестно». «Редактирует» (`EDITED_BY`) не снимается и не сравнивается — это занятость элемента, а не правка.
- **Ключ модели** (`ModelIdentity.Key` — имя подпапки журнала) менять только вместе с `ModelIdentity.LegacyKeysFor`: прежний ключ должен попасть в `LegacyKeys`, иначе история модели разделится. Так уже было: 01.10.2026 ключ модели на Revit Server перешёл с полного пути на GUID хранилища, и сентябрьская история перестала читаться.

## История переделки интерфейса

1. Компоновка: верхняя строка, фильтры в одну строку + «Ещё» + включённые фильтры с крестиком, подробности справа/снизу по ширине панели, строка состояния.
2. Таблица: 6 столбцов по умолчанию, остальные — правым щелчком по заголовку; «Равно / Не равно» из меню ячейки (были «Только/Кроме»).
3. Вкладка «События модели», «Следить за выделением», вкладка «История», операции одной строкой (▸).
4. Светлая/тёмная тема, следует за темой Revit.
5. После первого просмотра: окно настроек растягивается и прокручивается; время «ДД.ММ.ГГГГ ЧЧ:ММ»; «Сортировка и группировка» как в Revit (до 4 уровней, «Заголовок»); статус значком и текстом.

6. 3D-вид изменений (кнопка «3D», свой вид пользователя, цвета по итогу за период, легенда в панели).
8. Фильтр как в Revit (кнопка «Фильтр», «Равно / Не равно» в меню ячейки), «Скрыть отменённые», «Скрыть не попавшие» по умолчанию, актуализация всех «✗», полупрозрачные изменённые с изменениями внутри, габариты у элементов без точки вставки.
7. Ревью логики: «Без дублей» через границу периода, периоды «Вчера» и «С моей последней синхронизации», «Вернуть в журнал», общие настройки только для чтения, актуализация убрана с ленты, история вида без выделения, предупреждение о недоступной папке, вкладка «Было → стало».

В Revit ещё не проверено (риски): «Вернуть в журнал» у всей команды, период «С моей последней синхронизации» после реальной синхронизации, «Без дублей» для удалений, предупреждение о недоступной папке, окно настроек с общими разделами только для чтения; заголовки групп и прокрутка в свёрнутой группе, свои шаблоны ComboBox/полос прокрутки/заголовков таблицы, контекстные меню и подсказки в тёмной теме, Popup «Действие» в стыкуемой панели. 3D-вид: раскраска в стиле «Тонирование с кромками», рамка подрезки по этажам, удаление вида при закрытии вкладки (проверка в Idling), повторный показ при открытом виде, оставшийся вид при следующем открытии модели.
