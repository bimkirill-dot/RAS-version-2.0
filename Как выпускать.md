# Как выпускать RAS v. 2.0 — простыми словами

## Как это устроено

Есть три места:

1. **Ваш компьютер** — папка `D:\Code\RAS_v_2.0`. Здесь мы меняем плагин. Отсюда же запускаются все команды — файлы `.cmd` в корне папки, двойным щелчком.
2. **Сервер** — папка `\\10.10.1.77\Shared\BIM\00_Плагины\00_RAS\RAS_v_2.0`. Это «склад»: готовые версии плагина, установка для коллег, общие настройки, журналы.
3. **Компьютеры коллег** — на них стоит только маленький «загрузчик». При каждом запуске Revit он идёт на склад и берёт оттуда актуальную версию плагина.

## Что делает каждый файл

| Файл | Простыми словами | Что получают коллеги |
|---|---|---|
| `build.cmd` | Собрать и поставить новую версию **только себе** | ничего |
| `publish-setup.cmd` | Положить на склад **установку** для коллег (один раз) | могут установить плагин |
| `publish.cmd` | **Выпустить** новую версию: спросит «кому» и «что нового» | новую версию — после перезапуска Revit |
| `promote.cmd` | Тестовая группа проверила — **отдать всем** | все получают ту же версию |
| `rollback.cmd` | Новая версия плохая — **вернуть прежнюю** | прежнюю версию — после перезапуска Revit |
| `status.cmd` | **Посмотреть**, что сейчас лежит на полках «тест» и «все», когда выпущено и что нового; кто в тестовой группе. Ничего не меняет | ничего |

**Тестовая группа** — люди, которые получают новую версию первыми. Сначала это только вы. Список — на сервере в файле `Config\test-users.txt`: по одному логину Windows в строке (например, `Poletayev_BIM`).

## Что настраиваете вы — два файла

| Что | Файл | Как поменять | Когда действует |
|---|---|---|---|
| **Всё, что видят люди:** какие модули работают (блок `{Модули}`), группы людей (блок `{Люди}`), отделы и панели ленты, подписи кнопок, кому кнопка нажимается (`доступна="…"`) | `src\Core\ribbon.txt` в папке проекта | правка в Блокноте → `build.cmd` (вам) / `publish.cmd` (всем) | после перезапуска Revit |
| **Кто в тестовой группе** | `Config\test-users.txt` на сервере | правка прямо на сервере, логины Windows по одному в строке | при следующем запуске Revit, выпуск не нужен |

- Подсказка по всем словам — в начале самого `ribbon.txt`. Коды модулей и кнопок видны в Revit: «О плагине». Сейчас: модули `ModelHistory`, `ClashAnalysis`; кнопки `Core.About`, `ModelHistory.Journal`, `ModelHistory.History`, `ModelHistory.Settings`, `ClashAnalysis.ViewSettings`, `ClashAnalysis.ElementClashes`.
- Модуль: `работает` / `только тест` / `выключен` / `не загружать`. Кнопка работающего модуля видна всегда; кому недоступна — серая (в подсказке: «обратитесь к BIM-менеджеру»).
- Своя подпись и доступ — словами `подпись` и `доступна`: `ClashAnalysis.ElementClashes подпись="Коллизии элемента" доступна="руководители"`. Без слова строка пропускается.
- Ошибка в строке ничего не ломает и не прячет: строка пропускается, причина — в журнале ошибок (`%LocalAppData%\RAS_v_2.0\Logs\ras.log`).
- `ribbon.txt` — часть плагина: после правки его нужно закоммитить (ИИ сделает коммит, `git push` — вы).

## Первый раз

1. Закройте Revit, запустите `build.cmd`. Убедитесь, что у вас всё работает в Revit 2023 и 2026.
2. `publish-setup.cmd` → ответить «да». Установка для коллег появилась на сервере.
3. `publish.cmd` → «1 — тестовой группе» → написать, что нового (например: «Первая версия RAS v. 2.0»).
4. Удалить файл `%AppData%\RAS_v_2.0\loader.ini`. Сейчас ваш Revit берёт плагин прямо из папки проекта; без этого файла — со склада, как у коллег. Так вы увидите ровно то, что получат они.
5. Открыть Revit, проверить.
6. Всё хорошо — `promote.cmd`. Теперь версия у всех.
7. Коллегам: закрыть Revit, открыть `\\10.10.1.77\Shared\BIM\00_Плагины\00_RAS\RAS_v_2.0\Setup` и запустить `install.cmd`.

## Каждый следующий раз

1. Мы что-то поменяли. ИИ собирает, проверяет и делает коммит. Вы проверяете у себя в Revit (`build.cmd` ставит версию вам).
2. `publish.cmd` → «1 — тестовой группе» → «что нового» (коротко, для людей — это увидят пользователи).
3. Проверили — `promote.cmd`.

Срочное исправление можно выпустить сразу всем: `publish.cmd` → «2 — всем». Тогда и полка «тест» переводится на ту же версию — иначе тестовая группа (она всегда берёт «тест») осталась бы на старой.

## Если всё сломалось

- **Новая версия мешает работать:** `rollback.cmd` → покажет прежние версии → ввести номер той, что работала. Коллеги получат её после перезапуска Revit.
- **Мешает один модуль:** в `src\Core\ribbon.txt`, блок `{Модули}`, поставить ему `выключен` и сразу `publish.cmd all` — или `rollback.cmd` (как — в README, «Модули и кнопки у всех»).
- **`publish.cmd` прервался посередине:** ничего страшного — коллеги ничего не получили. Запустите ещё раз.

## Сайт коллизий

Сайт RAS-Clash Analysis работает на вашем компьютере и к выпуску плагина не относится.

- `site.cmd` — обновить сайт до текущей версии из папки проекта и запустить (откроется браузер, `http://localhost:5080`). Перед обновлением делается копия базы.
- `site.cmd start` — запустить (например, после перезагрузки компьютера), `site.cmd stop` — остановить.
- `site.cmd rollback` — новая версия сайта плохая: вернуть прежнюю. Данные не меняются.
- `site.cmd autostart` — чтобы сайт запускался сам при входе в Windows.
- `site.cmd firewall` — один раз: открыть порт сайта коллегам в брандмауэре (Windows спросит права администратора).

**Вход на сайт.** Без входа сайт не открывается. Первый раз откройте `http://localhost:5080` на своём компьютере — сайт предложит создать учётную запись администратора (только с этого компьютера). Коллегам учётные записи заводите вы: «Настройки» → «Учётные записи» — логин, имя, роль, временный пароль; пароль коллега сменит сам (своё имя в шапке сайта).

**Сайт для коллег, пока он на вашем компьютере:** «Настройки» → «Адрес сайта» → галочка «Доступен коллегам по сети» → `site.cmd stop`, `site.cmd start` → `site.cmd firewall`. Адрес для коллег — `http://WIN-QJI8IV2IK11:5080`. Сайт работает, пока ваш компьютер включён и не спит.

Окна у сайта нет: работает ли он — откройте `http://localhost:5080`. Если сайт пропал — в его журнале (`%LocalAppData%\RAS_v_2.0\RAS-Clash Analysis\Site\Журнал`) написано почему.

## Мелочи, которые стоит помнить

- `build.cmd` каждый раз снова переключает ваш Revit на версию из папки проекта. Это нормально, пока вы разрабатываете. Чтобы снова посмотреть «как у всех» — удалите `loader.ini` ещё раз.
- Если `build.cmd` пишет, что загрузчик «занят открытым Revit», — закройте Revit этой версии и запустите `build.cmd` ещё раз.
- `publish-setup.cmd` нужен повторно, только если ИИ скажет, что изменился загрузчик. Тогда коллегам придётся запустить `install.cmd` ещё раз — их нужно об этом предупредить.
- Выгружать изменения в GitHub — `git push` (ИИ напомнит).
